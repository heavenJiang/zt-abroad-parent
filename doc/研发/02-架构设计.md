# 架构设计

> **实施口径：** 已决定沿用 RuoYi 脚手架。本文中的模块名（`abroad-*`）、表前缀（`cat_`/`asm_`/`crm_`/`ai_`/`itg_` → `abr_`）、`tenant_id`、Flyway、MyBatis-Plus、`/admin/api` 等技术口径按 [00-RuoYi落地对照.md](00-RuoYi落地对照.md) 替换；代码规范以 [../开发规范.md](../开发规范.md) 为准。

## 架构总览

1a 用一个 Spring Boot 单体应用 + 一台云服务器跑通获客闭环；六个模块在代码上分开，部署上合在一起。

> 图：系统架构 · 1a（图在在线文档中查看：https://claude.ai/code/artifact/200d60ea-485b-410e-9a16-b59812fb71a8）

测评与选校引擎是核心：它不调用大模型，结果由 AI 网关负责写成解读文字。产品层面的完整蓝图（四大业务域、多租户、定制化）见产品设计文档，本页只描述当前要建的部分。

## 分层与模块边界

采用**模块化单体**：一个进程、一个数据库，但代码按业务模块划清边界，将来哪个模块需要单独部署也能拆。

**依赖规则**

1. `abroad-app` 依赖所有业务模块，只放 Controller、配置、启动类。
2. 业务模块（system、catalog、assessment、crm）只依赖 `abroad-common`，以及其他模块对外公开的 Service 接口和事件类。
3. 需要大模型的模块依赖 `abroad-ai` 的 `AiGateway` 接口；需要微信、存储的模块依赖 `abroad-integration` 的接口。
4. 禁止循环依赖；禁止跨模块读写表。用 ArchUnit 在测试里自动检查。

**模块间用事件解耦**（Spring 应用事件，事务提交后触发，并写入事件表便于重放）

| 事件 | 发布模块 | 订阅模块与动作 |
| --- | --- | --- |
| `AssessmentCompleted` | assessment | crm：创建或更新线索、计算意向度；ai：生成线索卡片 |
| `LeadAssigned` | crm | integration：企微通知负责顾问 |
| `LeadSlaDue` | crm（定时任务） | integration：提醒顾问；超时升级给负责人 |
| `ProgramRequirementChanged` | catalog（含 `intel_watcher` 自动生效） | assessment：标记受影响的结果；growth：项目页刷新、关注者与受影响线索提醒、快讯加急选题 |
| `PolicyChanged` | growth（`intel_watcher`） | growth：快讯加急选题、受影响线索提醒 |
| `CustomerBoundWechat` | integration | crm：合并同一人的多条记录 |
| `VisitorToolUsed` | assessment（入口工具） | crm：更新访客档案与线索评分；growth：归因 |
| `PlanMomentDetected` | assessment（我的申请规划：冲保失衡、不达标、材料不齐、家长查看、反复修改） | crm：线索评分；growth：`booking_agent` 推荐对应服务 |
| `LeadCaptured` | crm | growth：启动培育序列；ai：线索评分 |
| `ContentPublished` | growth | growth：归因起点（内容编号、口令） |
| `OfferAuthorized` | crm | growth：生成 offer 卡、进入内容素材库 |
| `CircuitBreakerTripped` | growth（编排器） | 暂停相关 Agent / 账号，通知负责人 |

获客自动化由**营销编排器**驱动（剧本、营销日历、事件、定时、预算与熔断），设计见《获客系统设计》（`doc/产品/06-获客系统设计.md`）；编排器和获客 Agent 放在 `zt-abroad` 的 `com.ygb.abroad.growth` 包，大模型调用仍只经 AI 网关。

## 关键流程：测评到顾问跟进

这是 1a 唯一必须端到端跑通的流程：学生从点开链接到拿到报告不超过 10 秒等待，顾问在学生完成测评后 1 分钟内收到通知。

1. **进入：** 学生从带渠道码的链接或二维码进入小程序 / H5，前端记录渠道码。
2. **同意：** 展示隐私政策，学生同意后创建 `asm_assessment`（匿名，只有设备标识和渠道码）。
3. **答题：** 分步提交答案，每步自动保存；可上传简历，由 AI 网关解析后预填，学生确认。
4. **登录：** 生成报告前微信登录，创建或匹配 `crm_customer`（按 unionid / 手机号哈希查重），把测评绑定到客户。
5. **计算：** 归一化生成 `asm_profile` → 选校引擎同步计算（纯 Java，目标 1 秒内）→ 写入 `asm_result`。
6. **报告：** 先返回结构化结果让页面立即展示档位和学校；解读文字由「测评解读」Agent 异步生成后推送到页面。AI 失败时用模板文字兜底，报告不能因 AI 失败而出不来。
7. **线索：** 发布 `AssessmentCompleted` → CRM 创建或更新线索、计算意向度、按规则分配顾问、设置 SLA 到期时间。
8. **通知：** 发布 `LeadAssigned` → 企微向顾问推送线索卡片；学生在报告页可预约解读或添加顾问企微。
9. **跟进：** 顾问在管理端线索看板或企微侧边栏看到客户、测评结果和卡片，记录跟进；SLA 超时自动提醒。

## AI 网关设计

所有大模型调用走同一条管道，业务方只传 Agent 编码和输入。

```
AiGateway.invoke(agentCode, input, context)
  1 读取 Agent 配置（生效提示词版本、主备模型、审核策略、超时与预算）
  2 去标识化：姓名、手机、证件、微信号 → 占位符
  3 可选检索：从院校库 / 知识库取事实并附来源
  4 渲染提示词 → 调用主模型；超时或报错 → 备用模型
  5 校验输出 JSON Schema；失败重试 1 次 → 仍失败返回降级结果
  6 输出过滤：录取承诺、广告违禁词、整篇文书
  7 还原占位符 → 按审核策略：直接返回，或进入审核队列
  8 写 ai_call_log（全程异常也要记）
```

**1a 用到的 Agent**

| 编码 | 做什么 | 审核策略 | 失败时 |
| --- | --- | --- | --- |
| `report_explainer` | 把引擎结果写成报告里的定位、每所学校理由、短板说明 | 直接展示 + 抽检 | 用模板文字 |
| `resume_parser` | 从简历 / 成绩单抽取问卷字段 | 学生确认后写入 | 提示手动填写 |
| `lead_card` | 生成顾问看的线索卡片（摘要、顾虑、开场话题） | 仅内部可见 | 只发基础信息 |
| `catalog_extractor` | 从院校官网页面抽取项目字段 + 原文引句 | 引句与取值校验通过自动入库（项目采集、情报监测）；编辑页预填由录入者保存 | 进例外队列 |

**获客 Agent（2026-10-14 加入 1a，全自动执行）**：发出前统一经过合规闸门（`compliance_checker`）、频控、预算与熔断；执行模式按 Agent 配置，新 Agent 以“全自动 + 高比例 AI 复核抽检”起步，指标达标自动升级、异常自动降级（MA-02）。

| 编码 | 做什么 | 执行模式 | 失败时 |
| --- | --- | --- | --- |

## 部署、环境与安全架构

**环境**

| 环境 | 位置 | 用途 |
| --- | --- | --- |
| 本地 | 开发机 Docker Compose | AI 开发与自测 |
| 测试 | 云服务器上独立的 Compose 项目和独立数据库 | 创始人验收、顾问试用、小程序体验版 |
| 生产 | 云服务器 | 正式使用 |

测试与生产的数据库、密钥、微信配置完全分开。

**发布**：合并到 `main` → CI 构建镜像 → 自动部署到测试环境 → 验收通过后手动触发生产部署；保留上一个镜像以便一键回滚。数据库迁移在应用启动时由 Flyway 自动执行。

**备份**：每天导出数据库到对象存储，保留 30 天；每月在测试环境做一次恢复演练。

**安全边界**

- 服务器只开放 80 / 443；SSH 仅密钥登录；数据库和 Redis 不对公网开放。
- 全站 HTTPS；密钥只在服务器的环境变量里，不进仓库、不进镜像。
- 管理端登录失败次数限制；学生端接口按 openid 和 IP 限流。
- 文件存储桶为私有，只通过临时链接访问。
- 微信回调校验签名。
