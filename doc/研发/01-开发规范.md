## 总则

系统主要由 AI 编写，人负责需求、验收和关键评审。**本规范的读者既是人也是 AI**：每一条都写成可以直接执行、可以检查的规则。

**适用范围**：留学智能体平台的全部代码、数据库脚本、提示词和配置。产品需求以「留学智能体平台 · 产品设计」为准，技术实现以本文档为准；两者冲突时停下来问人，不自行取舍。

**规范放在哪里**：仓库根目录放一份 `CLAUDE.md`（或所用 AI 编程工具的等效文件），内容为本规范的精简版，并链接到 `docs/` 下的完整规范、架构和任务卡。AI 每次开始任务前必须读取。

**AI 开发工作流**

1. **一张任务卡一个分支：** 任务卡从「开发计划」页取，写清目标、范围、验收标准。
2. **计划写进执行记录后直接动手：** AI 把实现计划（改哪些文件、新增哪些表和接口、怎么测）和决策（默认值与理由）写进任务卡执行记录，不等人确认（2026-10-20，尽量减少人工参与）。
3. **先测试后实现：** 有规则的逻辑（选校引擎、权限、计算）先写测试用例。
4. **自动验收后合并：** 完成定义由流水线自动检查（编译、测试、SQL 临时库双跑、接口实测与读回比对、页面冒烟、开发库还原、`mvn verify`），全部通过即合并并部署测试环境；创始人每周看变更摘要，发现问题回滚或开新卡。

**AI 必须停下等人确认的事（只有这些）**：删除生产数据、破坏性修改已上线的表结构、修改权限与安全逻辑、新增有许可或安全风险的第三方依赖、涉及法律文本与资金的规则。其余（含任务卡内的范围细节、默认参数）由 AI 按默认方案决定并记录。

## 仓库与目录结构

单仓库（monorepo），后端、管理端、学生端、文档放在一起，方便 AI 一次看到全貌。包名前缀待定，下文用 `com.xx.abroad` 示意。

```
abroad/
├── CLAUDE.md                  AI 必读：规范精简版 + 文档索引
├── docs/                      规范、架构、任务卡、决策记录
├── server/                    后端（Maven 多模块）
│   ├── abroad-app/            启动模块：配置、全部 Controller
│   ├── abroad-common/         工具、异常、响应体、基类（不含业务）
│   ├── abroad-system/         用户、角色、权限、审计、字典
│   ├── abroad-catalog/        院校库
│   ├── abroad-assessment/     测评、背景档案、选校引擎、报告
│   ├── abroad-crm/            客户、线索、跟进、渠道
│   ├── abroad-ai/             AI 网关、提示词、调用日志、审核队列
│   └── abroad-integration/    微信、企业微信、对象存储等外部对接
├── web-admin/                 员工管理端（Vue 3）
├── app-student/               学生端小程序 + H5（uni-app）
├── prompts/                   提示词模板与评测样例（版本化）
├── deploy/                    Docker Compose、Nginx、环境变量模板
└── seed/                      初始化数据：院校层次表、权重、测试用例
```

1b 之后按同样方式新增 `abroad-content`、`abroad-delivery`、`abroad-essay`。**模块之间只能通过对方的 Service 接口或事件交互，禁止直接读写对方的表。**

## 后端编码规范

- **分层：** Controller（只做参数校验和权限注解）→ Service（业务与事务）→ Mapper（数据访问）。Controller 禁止写业务逻辑、禁止直接调 Mapper。
- **包结构：** 每个模块 `com.xx.abroad.<模块>.{controller,service,service.impl,mapper,domain,dto,vo,event}`。对外暴露的只有 `service` 接口、`dto` 和 `event`。
- **命名：** 类大驼峰，方法和变量小驼峰，常量全大写下划线；实体与表名一一对应（表 `crm_lead` → `CrmLead`）。
- **异常：** 业务错误抛 `BizException(错误码, 提示)`，由全局异常处理器转为统一响应；禁止吞异常、禁止用 `null` 表示失败。
- **事务：** 多表写入的 Service 方法加 `@Transactional(rollbackFor = Exception.class)`；事务内不调用大模型和外部接口（慢调用会长时间占用连接）。
- **确定性代码与 AI 分开：** 选校打分、分档、权限判断等必须是纯 Java 确定性代码，禁止调用大模型。
- **日志：** SLF4J，JSON 格式输出，每条带 traceId；禁止打印手机号、证件号、token 等敏感信息；禁止 `System.out`。
- **配置：** 密钥、密码一律走环境变量，仓库只有 `.env.example`。
- **注释：** 类和 public 方法写中文 Javadoc；复杂业务规则在代码旁引用产品文档的章节名。
- **格式：** 使用 Spotless 自动格式化，提交前必须通过。

## 数据库规范

数据库为 PostgreSQL。

- **表名前缀按模块：** `sys_`（系统）、`cat_`（院校库）、`asm_`（测评）、`crm_`（CRM）、`ai_`（AI）、`itg_`（对接）；全部小写下划线，禁止用 SQL 关键字作字段名。
- **每张业务表必备字段：** `id bigint`（主键）、`tenant_id bigint not null`、`created_by`、`created_at timestamptz`、`updated_by`、`updated_at timestamptz`、`deleted boolean default false`（逻辑删除）。创业期只有一个租户，但 `tenant_id` 从第一张表就加上，查询由框架自动拼接。
- **注释：** 每张表、每个字段必须有 `comment on`。
- **类型：** 时间用 `timestamptz`；金额用 `numeric(12,2)`；枚举用 `varchar` 存英文编码（如 `RUSH`、`TARGET`、`SAFETY`）并在字典表登记；灵活结构（如问卷答案、引擎结果快照）用 `jsonb`，但会被查询或统计的字段必须单独建列。
- **敏感字段：** 手机号、证件号等在应用层加密后存储，另存一个哈希列用于查重。
- **迁移：** 只用 Flyway 脚本变更结构，文件名 `V<序号>__<说明>.sql`；已合并的脚本禁止修改，只能新增；禁止在脚本里 `drop table` 已上线的表。
- **索引：** 外键列和常用筛选列建索引，并以 `tenant_id` 开头。
- **种子数据：** 权重表、院校层次表、字典放在 `seed/`，用可重复执行的脚本导入（`on conflict do nothing / do update`）。

## 接口规范

- **风格：** REST + JSON。路径按端区分：管理端 `/admin/api/<模块>/<资源>`，学生端 `/app/api/<模块>/<资源>`，外部回调 `/callback/<来源>`。两端的鉴权方式不同，不共用接口。
- **统一响应：** `{"code": 0, "message": "ok", "data": {...}, "traceId": "..."}`；`code` 非 0 为错误，错误码按模块分段（如测评 2xxxx、CRM 3xxxx），在 `docs/error-codes.md` 登记。
- **分页：** 请求 `page`、`size`（最大 100），响应 `{list, total, page, size}`。
- **命名：** JSON 字段小驼峰；时间用 ISO 8601 带时区；金额用字符串传递。
- **校验：** 请求体用 DTO + Bean Validation 注解；对外返回 VO，禁止直接返回数据库实体。
- **文档：** 用 springdoc 自动生成 OpenAPI；每个接口写中文摘要。前端的请求代码从 OpenAPI 自动生成，保证前后端一致。
- **幂等：** 测评提交、线索创建、外部回调等可能重复的请求带请求 ID，服务端去重。

## 前端与小程序规范

- **语言：** 全部 TypeScript，开启严格模式；Vue 3 组合式 API（`<script setup>`）。
- **管理端：** 组件库 Element Plus；状态管理 Pinia；路由按模块分文件；权限控制到按钮级（无权限直接隐藏）。
- **学生端：** uni-app，同一套代码输出微信小程序和 H5；只用 uni-app 官方组件和少量经过确认的组件库；每个页面在 375px 宽度下必须可用。
- **接口调用：** 只用从 OpenAPI 自动生成的请求函数，禁止手写 URL。
- **目录：** `src/{api,pages,components,stores,utils,types}`；页面文件与产品文档中的页面名对应。
- **文案：** 对外文字集中放在 `src/locales/zh-CN.ts`，禁止「保录」「录取率 XX%」等承诺性用语。
- **格式：** ESLint + Prettier，提交前必须通过。

## AI 调用规范

这里的 AI 指系统运行时调用的大模型，不是写代码的 AI。

1. **只通过 AI 网关：** 业务代码只能调用 `abroad-ai` 模块的 `AiGateway.invoke(agentCode, input)`，禁止在业务模块里直接调大模型 HTTP 接口。
2. **提示词版本化：** 提示词放在 `prompts/<agentCode>/v<序号>.md`，启动时加载到数据库；代码里禁止写死提示词。
3. **结构化输出：** 需要程序读取的结果一律要求 JSON 并用 JSON Schema 校验；校验失败重试一次，再失败走降级逻辑。
4. **去标识化：** 传给大模型的内容不含姓名、手机号、证件号、微信号，由网关统一替换为占位符。
5. **事实必须有来源：** 院校要求、截止日等事实只能从院校库检索后传入，大模型的输出中引用的事实要能对应到库中记录；禁止让大模型凭记忆回答院校信息。
6. **输出过滤：** 网关统一拦截录取承诺、广告违禁词、整篇文书代写。
7. **审核策略：** 每个 Agent 在配置里声明「直接发出 / 人工确认后发出」，发给学生和家长的建议类内容默认人工确认。
8. **全量记录：** 每次调用记录 Agent、模型、提示词版本、输入摘要、输出、耗时、token、审核人。
9. **异步与超时：** 超过 3 秒的调用不阻塞用户请求，用异步任务 + 结果轮询或推送；单次调用设超时和预算上限。
10. **改提示词必须跑评测：** 每个 Agent 在 `prompts/<agentCode>/evals/` 下有样例，提示词或模型变更前跑一遍，结果不变差才能合并。

## 安全规范

- **鉴权：** 管理端用账号密码 + JWT（短有效期 + 刷新令牌），密码用 BCrypt；学生端用微信登录换取自己的令牌。两套令牌不互通。
- **权限：** 每个管理端接口必须声明权限点；数据权限（本人 / 全部）在 Service 层统一拼接；学生端接口只能访问自己的数据，由框架自动校验。
- **SQL：** 只用参数绑定，禁止拼接用户输入；排序字段走白名单。
- **文件：** 上传文件只存对象存储，校验类型和大小；访问用带有效期的临时链接。
- **敏感信息：** 传输全程 HTTPS；敏感字段加密存储、界面脚敏显示；查看全文和导出记审计日志。
- **同意与隐私：** 测评开始前展示隐私政策并记录同意版本；未同意不保存个人信息。
- **依赖：** 新增依赖须经人确认；CI 中做依赖漏洞扫描。
- **限流：** 测评提交、登录、AI 问答按用户和 IP 限流，防止刷接口和刷 AI 费用。

## 测试与质量门槛

AI 写的代码靠测试兑现可信度。下表是合并前必须满足的门槛，CI 自动检查。

| 对象 | 要求 |
| --- | --- |
| 选校引擎 | 每条规则有单元测试；`seed/engine-cases/` 中的全部案例（背景 → 期望档位）必须通过；行覆盖率 ≥ 90% |
| 权限与租户 | 每个接口有「无权限被拒绝」和「看不到别人数据」的测试 |
| 其他 Service | 核心路径有单元测试；行覆盖率 ≥ 70% |
| 数据库 | 用 Testcontainers 起真实 PostgreSQL 做集成测试，不用内存数据库代替 |
| 接口 | 每个接口至少一个成功用例和一个失败用例 |
| AI Agent | 评测样例全部跑通；结构化输出 100% 符合 Schema |
| 前端 | 关键流程（测评全流程、登录、线索列表）有端到端测试 |

**完成定义**：编译通过、所有测试通过、格式与代码检查通过、迁移脚本在干净库上可执行、OpenAPI 已更新、任务卡验收标准逐条自查并写在合并说明里。

## Git 与任务卡规范

- **分支：** `main` 只接受合并请求；每张任务卡一个分支，命名 `task/<任务号>-<简述>`（如 `task/M3-02-engine-scoring`）。
- **提交信息：** 中文，格式 `<类型>(<模块>): <做了什么>`，类型为 feat / fix / refactor / test / docs / chore。
- **合并说明：** 写清任务号、改动摘要、新增表和接口、测试情况、验收标准自查结果。
- **合并方式：** 压缩合并（squash），一张任务卡在 `main` 上只留一个提交。
- **任务卡大小：** 一张卡只做一件事，改动最好不超过 10 个文件。太大的卡先拆。
- **决策记录：** 重要技术决定（如换组件、改表结构的方案）记在 `docs/decisions/` 一事一文件，让后续的 AI 知道为什么。
- **任务卡模板** 见「开发计划」页。
