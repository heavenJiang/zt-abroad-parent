# 模块拆分

> **实施口径：** 已决定沿用 RuoYi 脚手架。本文中的模块名（`abroad-*`）、表前缀（`cat_`/`asm_`/`crm_`/`ai_`/`itg_` → `abr_`）、`tenant_id`、Flyway、MyBatis-Plus、`/admin/api` 等技术口径按 [00-RuoYi落地对照.md](00-RuoYi落地对照.md) 替换；代码规范以 [../开发规范.md](../开发规范.md) 为准。

## 端划分（2026-10-14 明确，优先于下文旧表）

**管理后台只给工作室员工用；面向学生和家长的是单独的 C 端前端；公开项目页是后端生成的静态页面。** 三者共用一个后端（`zt-admin` 单体 jar，业务在 `zt-abroad`），但接口分区、令牌、用户表、域名都分开，C 端永远访问不到管理接口。

| 端 | 给谁用 | 工程 | 技术 | 后端接口 | 身份 |
| --- | --- | --- | --- | --- | --- |
| 管理后台 | 工作室员工：负责人、顾问、新媒体 / 账号负责人、数据录入 | `zt-abroad-vue` | RuoYi-Vue3 + Element Plus | `/abroad/**`（及 RuoYi 自带 `/system/**`、`/monitor/**`、`/tool/**`） | `sys_user` + 员工令牌；`@PreAuthorize` 按钮级权限；顾问用 `@DataScope` 只看自己的线索 |
| C 端 | 学生、家长（含匿名访客） | `zt-abroad-uniapp`（M1-06 已建：请求封装只调 `/app/**`、匿名访客令牌、渠道码 `ch` / 内容编号 `ct` 透传） | uni-app（Vue 3）：先 H5，后微信小程序 | `/app/**` | 匿名访客 ID → 微信登录后的学生账号（`abr_app_user`，不进 `sys_user`）；学生令牌（Redis 前缀 `abr_app_token:`），与员工令牌互不通用 |
| 公开项目页 | 搜索引擎、AI 搜索、所有人 | 无单独工程：`zt-abroad` 用模板把院校库渲染成静态 HTML | 确定性模板 + 站点地图 + 结构化数据 | 不调接口；页面上的“测一下”“关注”跳转 C 端 | 无 |
| 第三方回调 | 微信、企业微信、开放平台 | — | — | `/callback/**` | `@Anonymous` + 验签 |

**工程命名**：统一为 `zt-<业务线>-<形态>`，业务线固定写 `abroad`，避免和同一工作区的其他产品线（如 `zt-vision-parent`、`zt-vue`）混淆：后端 `zt-abroad-parent`、管理后台 `zt-abroad-vue`、C 端 `zt-abroad-uniapp`。后端接口前缀 `/app/**`、包 `controller.app`、表 `abr_app_user` 中的 `app` 指“C 端”，不随工程名变化。

**为什么项目页不放进 C 端**：uni-app 的 H5 是单页应用，搜索引擎和 AI 搜索抓不到内容；项目页的数字又必须由模板直接取院校库。所以由后端在院校库变化时（`ProgramRequirementChanged`）重新生成静态文件，Nginx 直接提供，不经过 Spring，也扛得住爬虫。

**后端分区规则**（写进开发规范）

- 控制器分包：管理端 `com.ygb.web.controller.abroad`，C 端 `com.ygb.web.controller.app`，回调 `com.ygb.web.controller.callback`；Service、Mapper、领域对象在 `zt-abroad` 里共用，不复制业务逻辑。
- **C 端只返回专用 VO**，不直接返回管理端实体：线索评分、顾问备注、内部标签、引擎参考线 T / a、权重、录取概率等内部字段一律不出现在 `/app/**` 的响应里；学生只看到冲 / 稳 / 保。
- C 端按“本人”取数：从学生令牌（或匿名访客 ID）拿身份，不接受前端传入的用户 ID；匿名可用的接口（工具、项目查询）按访客 ID 和 IP 限流。
- C 端写操作不用 `@Log`（那是员工操作日志），改为写业务事件表 `abr_event`；员工查看学生明文敏感字段仍需单独权限并记录日志。

**域名与 Nginx 分流**（M1-07 已实现于 `deploy/nginx/templates/abroad.conf.template`，见 `deploy/README.md`；M10-06 上线时配 HTTPS）

| 域名（示例） | 内容 | 反向代理 |
| --- | --- | --- |
| `admin.<域名>` | 管理后台静态文件 | 只代理管理端接口和 RuoYi 自带接口，**不代理 `/app/**`**；可加 IP 白名单 |
| `m.<域名>` | C 端 H5 | **只代理 `/app/**`** |
| `www.<域名>` | 公开项目页静态文件、站点地图 | 不代理接口 |
| `api.<域名>`（或并入上面） | — | `/callback/**` 给第三方回调；小程序请求域名指向 `/app/**` |

**员工在哪里干活**：顾问和负责人日常在管理后台（线索收件箱、预约、例外队列、获客运营台）；即时提醒走企业微信应用消息，点开进入管理后台对应页面；账号负责人收到的“一键发布包”也推送到企业微信。企业微信侧边栏在 1b 做，仍属于员工端。

## 1a 功能点与验收标准

每个功能点对应开发计划里的一张或几张任务卡；验收标准就是任务卡的验收标准。**不在表里的功能 1a 不做。**

| 功能点 | 验收标准 |
| --- | --- |
| 员工登录 | 账号密码登录；连续 5 次失败锁定 15 分钟；令牌过期可刷新 |
| 角色与权限 | 预置「负责人 / 顾问 / 数据录入」3 个角色；顾问只看得到分配给自己的线索；无权限接口返回 403 且界面不显示入口（已实现：没有 `abroad:lead:all` 的员工，线索、预约、订单列表只含自己负责的，按 ID 访问别人的返回 403；“转给同事”用 `GET /abroad/lead/staff`，不需要用户管理权限） |
| 租户字段 | 所有业务表写入时自动填 `tenant_id`，查询自动带条件；有测试证明改不了其他租户数据 |

| 功能点 | 验收标准 |

## 1a 接口清单

下表是接口范围，请求和响应字段由对应任务卡在 OpenAPI 里定义。

**C 端 `/app/**`**（原设计写作 `/app/api`；下表为测评部分，申请规划、工具、关注、回填等接口见本节末尾补充）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/assessment/questionnaire/current`、`/assessment/questionnaire/{id}` | 取当前启用的问卷定义；按版本取（续答旧测评，草稿不可取） |
| POST | `/assessment` | 同意隐私政策后创建测评（带渠道码、请求 ID） |
| PUT | `/assessment/{id}/answers` | 分步保存答案（只提交本屏改动，null 表示清除；带断点屏 id） |
| GET | `/assessment/current`、`/assessment/{id}` | 断点续答：本人最近一次答题中的测评；按 ID 取本人测评 |
