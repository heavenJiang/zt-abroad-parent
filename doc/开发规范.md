# zt-abroad-parent 后端开发规范

> 适用范围：zt-abroad-parent（留学智能体平台，基于 RuoYi-Vue 3.9.2 二次开发，脚手架与 zt-vision-parent 相同，包名 `com.ygb`，数据库 PostgreSQL）后端全部模块。
> 第 1–13 章沿用 zt-vision-parent 开发规范（示例改为留学业务）；第 14 章为留学业务补充规范（AI 调用、选校引擎、个人信息、AI 开发流程）。
> 新增功能模块、修改既有模块均须遵守本规范；评审（Code Review）以本规范为准。
> 版本：v1.0（2026-10-13）

## 2. 架构设计

### 2.1 模块划分与依赖方向

```
                        ┌──────────────┐
                        │   zt-admin   │  启动入口 / Web 控制器 / 配置文件
                        └──────┬───────┘
          ┌──────────────┬─────┴────────┬───────────────┐
          ▼              ▼              ▼               ▼
   ┌────────────┐ ┌────────────┐ ┌──────────────┐ ┌────────────┐
   │zt-framework│ │ zt-quartz  │ │ zt-generator │ │ zt-abroad  │  留学业务
   └─────┬──────┘ └─────┬──────┘ └──────┬───────┘ └─────┬──────┘
         ▼              │               │               │
   ┌────────────┐       │               │               │
   │ zt-system  │       │               │               │
   └─────┬──────┘       │               │               │
         ▼              ▼               ▼               ▼
   ┌─────────────────────────────────────────────────────────┐
   │                        zt-common                        │  工具类 / 注解 / 基类 / 常量 / 异常
   └─────────────────────────────────────────────────────────┘
```

| 模块 | 职责 | 允许依赖 |
| --- | --- | --- |
| `zt-common` | 通用工具、注解、`BaseEntity`/`BaseController`/`AjaxResult`、常量、异常、过滤器 | 仅三方库 |
| `zt-system` | 系统管理领域：用户/角色/菜单/部门/岗位/字典/参数/公告/日志的 domain、mapper、service | `zt-common` |
| `zt-framework` | 框架装配：Security、JWT、数据源、AOP（日志/数据权限/限流/多数据源）、全局异常、Redis、线程池 | `zt-system` |
| `zt-quartz` | 定时任务管理与调度 | `zt-common` |
| `zt-generator` | 代码生成 | `zt-common` |
| `zt-abroad` | **留学业务**：domain、mapper、service，以及选校引擎 `engine`、AI 网关 `ai`、外部集成 `integration`、获客 `growth`（控制器在 `zt-admin`：管理端 `com.ygb.web.controller.abroad`，C 端 `com.ygb.web.controller.app`，回调 `com.ygb.web.controller.callback`） | `zt-common`（需要用户/部门数据时可加 `zt-system`） |
| `zt-admin` | 唯一启动模块：`ZtApplication`、全部 Web Controller、`application*.yml` | 以上全部 |

**强制规则：**

- 依赖只能自上而下，**禁止反向或横向依赖**（如 `zt-common` 引用 `zt-system`，`zt-quartz` 引用 `zt-generator`）。
- `zt-common` 不得包含任何业务逻辑和数据库访问。
- 所有第三方依赖版本统一在根 `pom.xml` 的 `<dependencyManagement>` 中声明，子模块不写版本号。

### 2.2 请求处理链路

```
HTTP 请求
 → Filter：RepeatableFilter / XssFilter / RefererFilter
 → Spring Security：JwtAuthenticationTokenFilter（Token 校验、续期）
 → Interceptor：RepeatSubmitInterceptor（@RepeatSubmit 防重）
 → Controller（@PreAuthorize("@ss.hasPermi(...)") 鉴权）
 → AOP：LogAspect(@Log) / DataScopeAspect(@DataScope) / RateLimiterAspect / DataSourceAspect
 → Service（业务、事务）
 → Mapper（MyBatis XML）→ PostgreSQL
 ← AjaxResult / TableDataInfo 统一返回
 ← GlobalExceptionHandler 统一异常处理
```

### 2.3 自动扫描约定（新模块不遵守将导致 Bean / Mapper 无法加载）

| 配置项 | 值 | 位置 |
| --- | --- | --- |
| 组件扫描根包 | `com.ygb`（`ZtApplication` 所在包） | `zt-admin` |
| Mapper 接口扫描 | `@MapperScan("com.ygb.**.mapper")` | `ApplicationConfig` |
| 实体别名 | `typeAliasesPackage: com.ygb.**.domain` | `application.yml` |
| Mapper XML | `classpath*:mapper/**/*Mapper.xml` | `application.yml` |

因此：**所有 Java 代码必须位于 `com.ygb` 包下；Mapper 接口放在 `*.mapper` 包；实体放在 `*.domain` 包；XML 放在 `resources/mapper/<模块名>/` 且文件名以 `Mapper.xml` 结尾。**

### 3.1 模块建立方式

**留学相关业务一律放在已建好的 `zt-abroad` 模块中**，约定如下：

| 项 | 约定 |
| --- | --- |
| 包名 | `com.ygb.abroad.{domain,mapper,service,service.impl,task,engine,ai,integration,growth}` |
| Mapper XML | `zt-abroad/src/main/resources/mapper/abroad/` |
| 控制器 | `zt-admin` → 管理端 `com.ygb.web.controller.abroad`（`/abroad/**`）；C 端 `com.ygb.web.controller.app`（`/app/**`）；第三方回调 `com.ygb.web.controller.callback`（`/callback/**`） |
| 表前缀 | `abr_`（如 `abr_school`、`abr_program`、`abr_lead`） |
| 权限标识 | `abroad:<资源>:<操作>`（如 `abroad:lead:list`） |
| 接口路径 | `/abroad/<资源>`（已加入 `xss.urlPatterns`） |
| 字典类型 | `abr_<含义>`（如 `abr_country`、`abr_lead_stage`） |
| 代码生成 | `generator.yml` 已设为 `packageName: com.ygb.abroad`、`tablePrefix: abr_`、`autoRemovePre: true` |

1. 新建模块 `zt-<业务名>`，`parent` 为 `com.ygb:zt-abroad-parent`，依赖 `zt-common`（需要用户/部门等系统数据时可依赖 `zt-system`）。
2. 根 `pom.xml`：`<modules>` 中加入模块；`<dependencyManagement>` 中声明 `com.ygb:zt-<业务名>:${zt.version}`。
3. `zt-admin/pom.xml` 中引入该模块。
4. 少量功能可直接放在 `zt-system` 中，但须使用独立子包与独立表前缀。

## 4. 分层编码规范

### 4.1 Controller

- 继承 `BaseController`，类上 `@RestController` + `@RequestMapping("/<模块>/<资源>")`。
- 每个接口**必须**声明权限：`@PreAuthorize("@ss.hasPermi('<模块>:<资源>:<操作>')")`；匿名接口使用 `@Anonymous`，并在评审中说明理由。
- 写操作（新增/修改/删除/导入/导出/授权等）**必须**加 `@Log(title = "...", businessType = BusinessType.XXX)`。
- 入参校验：`@Validated @RequestBody`，校验注解写在实体 getter/字段上。
- 分页列表：先 `startPage()`，紧接着**只执行一条**查询，再 `getDataTable(list)` 返回 `TableDataInfo`。
- 返回值统一 `AjaxResult`：`success(data)` / `error(msg)` / `toAjax(rows)`。
- 审计字段由 Controller 赋值：`setCreateBy(getUsername())`、`setUpdateBy(getUsername())`。
- 唯一性等前置校验放在 Controller 调 Service 的 `checkXxxUnique`，失败直接 `return error(...)`。
- Controller 中**禁止**编写业务逻辑、禁止直接调用 Mapper。

REST 约定：

| 操作 | 方法 | 路径 | 权限标识 |
| --- | --- | --- | --- |
| 列表 | GET | `/list` | `xxx:list` |
| 详情 | GET | `/{id}` | `xxx:query` |
| 新增 | POST | `/` | `xxx:add` |
| 修改 | PUT | `/` | `xxx:edit` |
| 删除 | DELETE | `/{ids}`（逗号分隔批量） | `xxx:remove` |
| 导出 | POST | `/export` | `xxx:export` |
| 导入 | POST | `/importData` | `xxx:import` |

### 4.2 Service

- 接口 `I<Xxx>Service` + 实现 `<Xxx>ServiceImpl`（`@Service`）。
- 业务异常抛 `ServiceException("提示信息")`，由全局异常处理器转为 `AjaxResult`，**禁止**吞异常或返回 `null` 表示失败。
- 涉及多表/多次写操作的方法**必须**加 `@Transactional`（需回滚受检异常时用 `rollbackFor = Exception.class`）。
- 数据权限过滤的查询方法加 `@DataScope(deptAlias = "d", userAlias = "u")`，并在 XML 中拼接 `${params.dataScope}`。
- 删除前需校验关联数据（参考 `SysPostServiceImpl.deletePostByIds` 的“已分配，不能删除”）。
- 缓存统一使用 `RedisCache`，key 前缀定义在 `CacheConstants`（格式 `业务名:`）；字典读取使用 `DictUtils`。

### 4.3 Mapper / XML

- Mapper 接口方法命名：`selectXxxList`、`selectXxxById`、`insertXxx`、`updateXxx`、`deleteXxxById`、`deleteXxxByIds`、`checkXxxUnique`。
- XML 必须定义 `resultMap`，公共查询列抽取为 `<sql id="selectXxxVo">`。
- 动态条件使用 `<where>`/`<if>`/`<set>`/`<trim>`/`<foreach>`。
- **一律使用 `#{}` 绑定参数**；`${}` 仅允许用于 `${params.dataScope}` 以及经过 `SqlUtil.escapeOrderBySql` 白名单校验的排序字段。
- 自增主键插入：`useGeneratedKeys="true" keyProperty="xxxId"`（建议同时写 `keyColumn="xxx_id"`）。
- SQL 方言要求见第 6 章。

### 4.4 Domain（实体）

- 继承 `BaseEntity`（已含 `searchValue/createBy/createTime/updateBy/updateTime/remark/params`），树形结构继承 `TreeEntity`。
- 字段类型与数据库类型严格对应（见 6.3），主键统一 `Long`。
- 需要导出的字段加 `@Excel`；敏感字段加 `@Sensitive(desensitizedType = ...)`；不允许序列化的字段（如密码）加 `@JsonIgnore`。
- 重写 `toString()`（`ToStringBuilder` + `MULTI_LINE_STYLE`），与既有代码保持一致。

## 6. PostgreSQL 开发规范（重点）

本项目由 MySQL 迁移而来，以下规则均来自迁移中实际踩到的问题，**新代码必须遵守**。

### 6.1 禁止使用的 MySQL 语法

| 禁止（MySQL） | 应使用（PostgreSQL） |
| --- | --- |
| 反引号 `` `query` `` | 不加引号（字段名避免关键字）；必要时双引号 `"user"` |
| `ifnull(a, b)` | `coalesce(a, b)` |
| `cast(x as char)`（MySQL 中表示任意长度字符串） | 直接查询 `text` 列，或 `cast(x as varchar)`；PG 中 `char` 等于 `char(1)`，会把内容**截断为 1 个字符** |
| `sysdate()` | `now()` |
| `date_format(x, '%Y%m%d')` | `to_char(x, 'YYYYMMDD')`（仅用于**时间列**） |
| `find_in_set(id, ancestors)` | `position(',' \|\| cast(#{id} as varchar) \|\| ',' in ',' \|\| ancestors \|\| ',') > 0` |
| `insert ignore` | `insert ... on conflict (唯一键列) do nothing` |
| `on duplicate key update` | `insert ... on conflict (唯一键列) do update set ...` |
| `LAST_INSERT_ID()` / `@变量` | `useGeneratedKeys`，或 `insert ... returning id` |
| `limit a, b` | 分页交给 PageHelper；手写用 `limit b offset a` |
| `auto_increment` | `bigserial` / `serial` |
| `datetime` / `tinyint` / `int(11)` | `timestamp` / `smallint` / `integer` |
| `engine=innodb`、列级 `comment '...'` | 删除；用 `comment on column` |

### 6.2 类型必须严格匹配（PG 不做隐式转换）

1. **char 列与字面量比较必须加引号**：`status = '0'`，禁止 `status = 0`（报错 `character = integer`）。
2. **Java `String` 写入整型列必须显式转换**：`is_frame = cast(#{isFrame} as integer)`。
3. **Java `boolean` 写入 `smallint` 列必须显式转换**：`cast(#{menuCheckStrictly} as integer)`。
4. **时间区间参数是字符串**，必须转换后再与时间列比较：

   ```xml
   <!-- 按天（前端 daterange，格式 yyyy-MM-dd） -->
   <if test="params.beginTime != null and params.beginTime != ''">
       AND create_time &gt;= cast(#{params.beginTime} as date)
   </if>
   <if test="params.endTime != null and params.endTime != ''">
       AND create_time &lt; cast(#{params.endTime} as date) + interval '1 day'
   </if>

   <!-- 精确到秒（前端 datetimerange，格式 yyyy-MM-dd HH:mm:ss） -->
   AND oper_time &gt;= cast(#{params.beginTime} as timestamp)
   ```

   禁止 `to_char(#{params.beginTime}, ...)`（`to_char(varchar)` 不存在），也不要对列套函数（会使索引失效）。

5. 新表设计时优先让列类型与 Java 类型一致，避免依赖 cast：
   标志位用 `char(1)` ↔ `String`；数量/排序用 `integer` ↔ `Integer`；主键用 `bigint` ↔ `Long`；布尔用 `boolean` ↔ `Boolean`。

### 6.3 类型映射表

| PostgreSQL | Java | 说明 |
| --- | --- | --- |
| `bigint` / `bigserial` (`int8`) | `Long` | 主键、外键 |
| `integer` / `smallint` (`int4`/`int2`) | `Integer` | 排序、数量 |
| `numeric(p,s)` | `BigDecimal` | 金额**必须**用 numeric + BigDecimal |
| `varchar(n)` / `char(n)` (`bpchar`) / `text` | `String` | |
| `timestamp` / `date` | `java.util.Date` | 配合 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")` |
| `boolean` | `Boolean` | |

### 6.4 主键与序列

- 主键使用 `bigserial`；初始化脚本中插入了**显式 ID** 的种子数据后，**必须**重置序列，否则后续插入主键冲突：

  ```sql
  alter sequence biz_order_order_id_seq restart with 100;
  -- 或：select setval('biz_order_order_id_seq', (select max(order_id) from biz_order));
  ```

### 6.5 其他

- 标识符一律小写、不加引号（PG 会把未加引号的标识符折叠为小写）。
- 模糊查询使用 `like concat('%', #{x}, '%')`（PG 支持 `concat`）；不区分大小写时用 `ilike`。
- 新功能上线前须在本地 PostgreSQL 15 上**实际执行**全部 SQL（含带时间区间、分页、排序的查询），不能只看编译通过。
- 自测须“保存后再读回”逐字段比对（新增 → 详情、修改 → 详情），只看接口返回“操作成功”不足以证明数据正确。

## 7. 数据库脚本管理

- 所有脚本放在 `sql/` 目录，**根目录不放 SQL 文件**。
- 全量脚本：`zt_<yyyyMMdd>_postgre.sql`；增量脚本：`update_<yyyyMMdd>_<业务名>.sql`。
- 增量脚本应可重复执行：`create table if not exists`、`alter table ... add column if not exists`、`insert ... on conflict do nothing`。
- 新增菜单/按钮、字典、参数配置需一并提交 SQL（代码生成器 `sql.vm` 已生成 PG 版本菜单脚本，可直接使用）。
- 禁止在脚本中使用 `drop table` 处理已上线的表；变更需评审。

## 8. 安全规范

- 鉴权：所有接口默认需要登录；`@PreAuthorize` 必写；超级管理员判断使用 `SecurityUtils.isAdmin(userId)`。
- 匿名访问：仅通过 `@Anonymous` 或 `SecurityConfig` 中显式放行。
- 密码：只能使用 `SecurityUtils.encryptPassword()`（BCrypt）存储，任何接口不得返回密码字段。
- 数据权限：涉及部门/用户数据的列表查询必须加 `@DataScope`。
- 防重复提交：表单提交类接口按需加 `@RepeatSubmit`；对外开放接口按需加 `@RateLimiter`。
- XSS：`xss.urlPatterns` 覆盖新模块路径（如 `/biz/*`）；富文本字段接口加入 `excludes` 并在后端自行过滤。
- 文件上传：使用 `FileUploadUtils`（已有后缀、大小、文件名长度校验），禁止自行拼接路径写文件。
- 配置安全：生产环境**必须**修改 `token.secret`、数据库密码、Druid 控制台账号密码（`login-username/login-password`），并通过 profile（`application-prod.yml`）或环境变量注入，**禁止**将生产凭据提交到仓库。

## 9. 日志与异常

- 使用 SLF4J：`private static final Logger log = LoggerFactory.getLogger(Xxx.class);`，**禁止** `System.out` / `printStackTrace()`。
- 业务异常：`throw new ServiceException("...")`；不要在 Controller 中 `try/catch` 后返回通用错误。
- 操作日志由 `@Log` 自动异步写入 `sys_oper_log`，不需手动记录。
- 日志目录在 `logback.xml` 中配置（默认 `/home/zt/logs`），部署时按环境调整。
- 国际化提示放在 `zt-admin/src/main/resources/i18n/messages.properties`，通过 `MessageUtils.message(key)` 获取。

## 10. 代码生成器使用规范

1. 在 PostgreSQL 中按第 5、6 章建表（**必须带表注释和字段注释**）。
2. 按需修改 `zt-generator/src/main/resources/generator.yml`：`author`、`packageName`（如 `com.ygb.biz`）、`tablePrefix`（如 `biz_`）、`autoRemovePre`。
3. 系统工具 → 代码生成 → 导入表 → 编辑（核对 Java 类型、查询方式、显示类型、字典）→ 生成。
4. 生成代码按第 3 章目录放置；`sql.vm` 生成的菜单 SQL 直接在库中执行，再到角色管理中分配权限。
5. 生成代码只是起点，提交前必须按本规范补充校验、事务、数据权限和单元/接口测试。

## 11. 代码风格

- 编码 UTF-8，缩进 4 个空格；Java 大括号**另起一行**（与现有代码保持一致）。
- 类和 public 方法写中文 Javadoc（说明、`@param`、`@return`）；类注释带 `@author`。
- import 不使用通配符；删除未使用的 import 与代码。
- 依赖注入沿用现有风格 `@Autowired` 字段注入（新代码也可使用构造器注入，但同一类内保持一致）。
- 字符串判空使用 `StringUtils`（`com.ygb.common.utils.StringUtils`），集合判空使用 `StringUtils.isEmpty(list)`。
- 时间处理使用 `DateUtils`；对象拷贝使用 `BeanUtils`；类型转换使用 `Convert`。
- Windows 脚本（`*.bat`）保持 **GBK 编码 + CRLF 换行**，否则中文乱码或无法执行；其余文本文件 UTF-8。

## 14. 留学业务补充规范

> 来源：《研发文档 · 开发规范》（`doc/研发/01-开发规范.md`）中与 RuoYi 脚手架不冲突的部分。两者冲突时以本文件为准。

### 14.1 包内分工

| 包 | 职责 | 约束 |
| --- | --- | --- |
| `com.ygb.abroad.engine` | 选校引擎：按学段（`abr_degree`：高中 / 本科 / 硕士 / 博士）选择策略；硕士为硬门槛、综合分 C = Σ w·s、录取概率 P = 1/(1+e^{-a(C−T)})、冲稳保分档；美本、美高为学术匹配；博士只做匹配不分档 | **纯 Java**：不访问数据库、不调用大模型、不持有 Spring Bean 状态；参数（权重、阈值、国家适配）由 Service 读取后传入；同一输入必须得到同一输出 |
| `com.ygb.abroad.ai` | AI 网关：脱敏 → 检索 → 主备模型 → 结构校验 → 输出过滤 → 审核策略 → 调用日志 | 业务代码**只能**通过网关调用大模型，禁止在 Service 中直接调用模型 SDK/HTTP |
| `com.ygb.abroad.integration` | 企业微信、微信小程序、对象存储等第三方接口 | 第三方密钥只从配置/环境变量读取；回调接口验签 |
| `com.ygb.abroad.growth` | 获客自动化：营销编排器（剧本、日历、事件、定时）、获客 Agent 的业务编排、合规闸门、频控、预算与熔断 | Agent 的大模型调用只经 `ai` 网关；对外发送只经 `integration` 的渠道适配器；只用平台官方接口，禁止模拟点击、群控；情报采集只抓白名单内的公开官方页面，遵守 robots、低频，禁止爬取内容平台的帖子、评论和用户信息 |
| `com.ygb.abroad.task` | 定时任务（已在 Quartz 调用白名单 `Constants.JOB_WHITELIST_STR` 中） | 时间边界按北京时间在 Java 中计算后传入 SQL |

### 14.2 AI 调用

- 发送给大模型前必须脱敏：姓名、手机号、微信号、证件号等替换为占位符，返回后再还原。
- 输出必须是约定的 JSON 结构并做 schema 校验，校验失败重试一次后转人工，不得把原始输出直接展示给学生。
- 每次调用记录：场景（agent 名）、模型、提示词版本、输入摘要、耗时、token、结果状态；提示词按版本保存，不在代码里硬编码长提示词。
- 审核策略按 Agent 配置（`直接发出` / `顾问确认后发出` / `禁止 AI 生成`），以《架构设计》Agent 表为准：报告解读 `report_explainer` 直接展示 + 抽检（失败时用模板文字）；发给学生、家长的个性化建议类内容（方案、文书建议等）默认顾问确认后发出。所有 AI 内容页面标明“AI 生成”。
- 获客 Agent（《获客系统设计》）默认全自动执行，但每条对外内容和消息发出前**必须**经过合规闸门（违禁词、录取承诺、导流用语、事实与院校库核对、AI 标识）、频控与免打扰、预算闸；熔断与一键暂停必须可用。自动消息中关于学生本人的结论只能取自选校引擎输出和院校库事实，不得由大模型自由生成选校建议。
- 价格、产品、营销日历、剧本、词表均为配置，禁止写死在代码或提示词中。
- 学生只看到冲 / 稳 / 保分档，**不展示录取概率百分比**；博士不分档，只给匹配清单。

### 14.3 个人信息

- **未成年人**：未满 14 周岁的信息只能由监护人（家长账号）提供并同意，按儿童个人信息规则处理；14–17 周岁须关联家长账号；营销触达只发给成年人；代码中按 `is_minor` / 年龄段控制，不得只靠前端隐藏。

- 学生手机号、微信号、证件号、成绩单等字段在实体上加 `@Sensitive`；查看明文需单独权限并记录操作日志。
- 测评附件、简历通过 `FileUploadUtils` 上传；生产环境存对象存储，不放公网可直接访问的路径。
- 定制输出按“每家客户独立部署一套”交付，不做多租户，表中不加 `tenant_id`。

### 14.4 测试门槛

- `engine` 包单元测试覆盖率 ≥ 90%，每个国家至少有正、反、边界三类样例；改权重或公式时同步更新样例。
- 其他 Service 关键路径（测评提交 → 报告 → 线索分配）有接口级自测记录；涉及 SQL 的改动必须在 PostgreSQL 15 上实际执行。

### 14.5 AI 编写代码的工作流

- 系统主要由 AI 编写：每个开发任务以“任务卡”下达（目标、涉及表/接口/页面、验收标准、依赖），模板与任务列表见 `doc/研发/05-开发计划.md`。
- AI 开发前必须读 `CLAUDE.md`、本规范与任务卡涉及的设计章节；一次只做一张任务卡，提交信息写明任务卡编号（如 `M3-04 选校引擎综合分计算`）。
- 人工评审重点：权限注解、SQL 方言、AI 调用是否经网关、个人信息是否脱敏、验收标准是否逐条满足。

### 14.6 管理端与 C 端分离

- **管理后台只给工作室员工用**（`zt-abroad-vue`，接口 `/abroad/**`，`sys_user` + 员工令牌）；**学生和家长只用 C 端**（`zt-abroad-uniapp`，接口 `/app/**`，`abr_app_user` + 学生令牌，Redis 前缀 `abr_app_token:`）。两种令牌互不通用，学生账号不进 `sys_user`。
- `/app/**` 控制器只返回 C 端专用 VO，禁止直接返回管理端实体；线索评分、顾问备注、内部标签、引擎参考线与权重、录取概率等内部字段不得出现在 C 端响应中。
- C 端接口的“本人”身份只从学生令牌或匿名访客 ID 取得，不接受前端传入的用户 ID；匿名接口按访客 ID 和 IP 限流（`@RateLimiter`）。
- C 端写操作记业务事件（`abr_event`），不使用员工操作日志 `@Log`。
- 匿名身份用访客令牌（请求头 `X-Visitor-Token`，库里只存哈希）；C 端控制器类上加 `@Anonymous`，并对每个接口加 `@RateLimiter(limitType = LimitType.IP)`。
- 学生填写的文本按纯文本保存和展示：测评答案接口不经 XSS 过滤（避免把 `>` 改成 `&gt;`），由后端拒绝类似 HTML 标签的输入；C 端和管理后台展示学生文本一律用文本插值，禁止 `v-html`。
- 公开项目页由后端模板生成静态 HTML（数字只取院校库），不经过 C 端前端，也不调用大模型。
- 部署时按域名分流：管理后台域名不代理 `/app/**`，C 端域名只代理 `/app/**`，详见《模块拆分·端划分》。
