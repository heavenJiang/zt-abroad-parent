| 国家 | 上线批次（§8） | 默认稳定度 a | T 整体偏移 | 难度档 D1 / D2 / D3 / D4 / D5 的默认 T |

| 澳洲 | 1 | 0.20 | 0 | 85 / 78 / 72 / 66 / 58 |
| 新加坡 | 1 | 0.12 | 0 | 92 / 87 / 82 / 76 / 70 |
| 美国 | 2 | 0.08 | +2 | 90 / 84 / 78 / 72 / 64 |
| 日本 | 3 | 0.06 | 0 | 85 / 78 / 70 / 62 / 55 |
| 韩国 | 3 | 0.10 | 0 | 85 / 78 / 70 / 62 / 55 |
| 德国 | 3 | 0.15 | 0 | 88 / 80 / 72 / 65 / 58 |

- **a 的含义**：a 越大，综合分略高于参考线就很快变成「保」。按 35% / 70% 分界反算，「稳」档覆盖的分差是 C − T ∈ [−0.619 / a, +0.847 / a]：英国 a = 0.18 时约 −3.4 到 +4.7 分；美国 a = 0.08 时约 −7.7 到 +10.6 分，更多学校会落在「稳」，更少给「保」。这就是 §8 说的美国「不确定性大、档位偏保守」；美国另外把 T 整体抬高 2 分。
- **T 用难度档而非具体学校**：冷启动期 T 来自「顾问按经验给的难度分（五档）」（§4）。顾问在录入项目（M2-08）时给每个项目定 D1–D5，系统按上表生成参考线并标明来源「顾问难度分」，以后再被工作室案例或官方统计覆盖。档位说明里的排名区间（如「约前 10 名院校的热门项目」）只是帮助定档的参考。
- **分档阈值**：所有国家都是冲 P < 35%、稳 35%–70%、保 P > 70%（§4）。学生端只显示冲 / 稳 / 保，概率只在管理端和测试台出现。

## 3 算例：一个虚构学生对两个虚构项目

用英国草案（`uk_master.json`）手算一遍，顾问可以据此检查公式是否合理。学生和项目都是虚构的。

**学生**：211 院校，本专业，百分制均分 85，专业排名前 30%；无科研；一段 3 个月相关实习（一般公司）；一项省级竞赛；雅思 6.5（最低小分 6.0）；申请商科，没考 GMAT。

**项目**：
- 项目 A：「示例大学 A · 管理学硕士」（虚构），顾问定为 D2，项目尚无自己的参考线 → T = 82，a = 0.18。
- 项目 B：「示例大学 B · 管理学硕士」（虚构），顾问定为 D4 → T = 70，a = 0.18。

### 3.1 子分（0–100）

| 维度 | 计算 | 子分 |
| --- | --- | --- |
| 院校层次 + GPA | 211 基础分 72 + 斜率 3 ×（85 − 英国 211 门槛均分 80）+ 排名前 30% 加 1 = 72 + 15 + 1 | **88** |
| 专业相关度 | 本专业 100，无缺先修课 | **100** |
| 标化 | 英国权重 0，不计算 | — |
| 科研 | 无科研 | **20** |
| 实习 / 工作 | 有效月数 = 3 × 0.7（一般公司）× 1.0（相关）= 2.1；20 + 80 × (2.1 ÷ 6) = 20 + 28 | **48** |
| 其他软背景 | 省级，1 项 | **60** |

### 3.2 综合分 C

```
C = 0.65 × 88 + 0.15 × 100 + 0 × — + 0.05 × 20 + 0.10 × 48 + 0.05 × 60
  = 57.20   + 15.00     + 0     + 1.00      + 4.80      + 3.00
  = 81.00
```

### 3.3 硬门槛（项目缺要求记录，用兜底值并标「要求待核实」）

| 项目 | 语言兜底（总分 / 小分） | 211 最低均分兜底 | 学生 | 结论 |
| --- | --- | --- | --- | --- |
| A（D2） | 6.5 / 6.0 | 80 + 4 = 84 | 6.5 / 6.0，均分 85 | 通过 |
| B（D4） | 6.0 / 5.5 | 80 − 2 = 78 | 6.5 / 6.0，均分 85 | 通过 |

### 3.4 录取可能性 P 与档位

```
项目 A：C − T = 81 − 82 = −1
        a × (C − T) = 0.18 × (−1) = −0.18
        P = 1 / (1 + e^{0.18}) = 1 / (1 + 1.1972) = 0.4551   → 35%–70% → 稳

项目 B：C − T = 81 − 70 = 11
        a × (C − T) = 0.18 × 11 = 1.98
        P = 1 / (1 + e^{−1.98}) = 1 / (1 + 0.1381) = 0.8787  → > 70% → 保
```

学生在报告里看到的只有：**项目 A「稳」，项目 B「保」**。0.4551、0.8787 只在管理端出现。

### 3.5 延伸：难度更高的项目和差距反算（§3、§6）

- 若同一学生申请一个 D1 项目（T = 88）：先看硬门槛，兜底要求是雅思 7.0 / 6.5、211 均分 80 + 7 = 87，学生两项都不够，项目归入「补足后可申」，不进冲稳保。假如项目库里的真实要求更低、硬门槛通过，则 P = 1 / (1 + e^{1.26}) = 0.2210 → 冲。
- 差距反算（只在语言、标化、科研、实习里找）：进入稳档需要 P ≥ 0.35，即 C ≥ 88 + ln(0.35 / 0.65) / 0.18 = 88 − 3.44 = 84.56，差 3.56 分。增加一段相关课题组经历（科研 20 → 55，C + 0.05 × 35 = +1.75）、再做 3 个月相关实习（实习 48 → 76，C + 0.10 × 28 = +2.80）后 C = 85.55，P = 0.3915 → 稳。这类结论正是 §6 说的「顾问服务切入点」。

## 4 校准流程：M6-03 怎么用这些案例

```
M0-06 顾问确认草案（status: confirmed，版本 v1）＋ 整理 20–30 个案例（cases.csv）
  → M3-05 / M3-07 引擎实现，导入 v1
  → M3-08 测试台跑全部案例：命中率、混淆矩阵、不一致清单
  → M2-08 项目录入（200–300 个），案例涉及的项目都定好难度档
  → M6-03 逐条分析 → 调参 → 新版本 → 重跑，直到达到创始人设定的命中率
  → M6-06 上线；之后录取结果回流，约 200 条 / 国后用逻辑回归重拟合（§7）
```

M6-03 的具体做法：

1. **先锁定留出集**：调参之前，每个国家随机留出约 1/3 案例（每国至少 1 条）不参与调参，只用于最后验收。20–30 条样本很少，不留出就很容易“调到全对、上线全错”。
2. **逐条看不一致案例**，按以下顺序判断原因，前面的原因优先修：
   1. 数据错误（案例填错、换算错）→ 改案例；
   2. 硬门槛误判（被判「补足后可申」却录取了）→ 补项目库要求或改兜底值；
   3. 项目难度档定错 → 改该项目的档位或给它单独的 T（最常见，也最安全）；
   4. 某国整体偏乐观或偏保守 → 调该国的 `t_offset` 或 a；
   5. 同一方向的偏差在 3 条以上案例中重复出现 → 才考虑调权重或子分参数。
3. **每次改动都升版本**（如 `UK_MASTER-2026.11.2`），重跑全部案例，在本文末尾的「校准记录」里写：改了什么、为什么、前后命中率。
4. **AI 可以协助**：对 T 偏移和 a 在小范围内做网格试算，列出每种组合的命中率供顾问选择；但不自动采用，最终由顾问决定、创始人确认。
5. **验收**：留出集上的命中率达到创始人设定的目标（见第 5 节）后，配置改为启用；未达标的国家保持 `draft`，不对学生开放该国测评。
6. **上线后**：顾问在工作台把档位改掉时记录原因（§7 第 2 条），录取结果回流案例库；每季按「各档实际录取率」做一次校准检查（保 > 70%、稳 35%–70%、冲 < 35%）。

## 5 需要创始人设定的命中率目标

上线门槛写的是「引擎在已知案例上的各档命中率达到创始人设定的值」（《开发计划》）。需要创始人定下面几件事（命中率口径见 `seed/engine-cases/README.md` 第 4 节）：

| 要定的事 | 说明 | AI 建议的起点（仅供参考） |
| --- | --- | --- |
| 主指标 | 引擎档位与顾问档位一致的比例（每档 + 整体） | 用它作上线门槛 |
| 整体命中率目标 | 留出集上的整体一致率 | ≥ 70% |
| 每档命中率目标 | 冲、稳、保各自的一致率 | 每档 ≥ 60% |
| 严重错档容忍度 | 冲 ↔ 保相差两档的案例数 | 0 |
| 「保」档的底线 | 引擎判「保」而实际被拒的案例 | 每国不超过 1 条，且逐条有解释 |
| 按国家还是看整体 | 第 1 批三国是否各自达标才能上线 | 各国分别达标；不达标的国家延后 |
| 结果一致性是否作门槛 | 各档实际录取率；20–30 条样本时每组远少于 10 条 | 只作参考，不作门槛 |

为什么不追求 100%：顾问档位本身是主观判断，样本又少，调到 100% 基本意味着过拟合。比数字更重要的是**严重错档为 0**，以及每一条不一致都能说清楚原因。

## 7 风险与说明

- **样本量很小**：20–30 条案例只能发现明显的偏差，不能证明引擎“准确”。上线后仍要靠顾问修正与录取结果回流（§7），约 200 条 / 国后才重拟合。
- **学生不应看到概率**：冷启动期数字不准，且容易被理解为录取承诺（§4）；P 只在管理端和测试台出现。
- **兜底值只是兜底**：硬门槛以项目库（带来源 URL 的官网要求）为准；用了兜底值的结果会标「要求待核实」。英国各校对中国院校的分层要求、APS、语言要求等以各校和官方最新公布为准。
- **字段编码**：与问卷初稿（M0-04）一致；问卷或院校库学科大类定稿时如有改名，参数文件、案例模板需同步修改。
