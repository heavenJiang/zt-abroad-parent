通用约定：学生端只显示冲 / 稳 / 保档位，任何页面不出现录取百分比；AI 生成的内容都标「AI 生成」并有失败兜底；示例中的学校、人名、数字都是占位。

## 学生端

### 01 落地页

- **目的**：学生从内容、海报、讲座二维码进入的第一屏，让人点「开始免费测评」。
- **主要区域**：工作室名称与 Logo；一句话价值「3 分钟测出你能申哪些学校」+ 切入人群副标题；真实测评人数（人数少时隐藏）；「测完你会得到」（三档代表校、六维画像、关键短板 + 模糊示例报告）；三步流程（答题 → 微信登录 → 出报告）；主按钮；隐私说明与免责。
- **关键交互**：主按钮进入隐私同意页，同意后 `POST /app/api/assessment` 创建测评（带渠道码）；有未完成测评时按钮变为「继续上次测评（第 N / 5 步）」；渠道码从链接或小程序码 scene 读取，前端暂存。
- **覆盖验收**：答题与断点（未登录也能答题、从上次位置继续）；渠道码（测评带渠道码用于统计）；产品文档「不要求登录、只显示真实测评人数」。

### 02 问卷步骤页 × 5

- **目的**：手机上 3–5 分钟答完 5 步：目标 / 学术 / 语言与标化 / 经历 / 偏好。
- **主要区域**：5 步题目条带；放大画「学术」「经历」两步：顶部「第 N 步 / 共 5 步」+ 分段进度条 + 「已自动保存」；每屏不超过 4 题；底部上一步 / 下一步。
- **关键交互**：
  - 每步自动保存（`PUT /app/api/assessment/{id}/answers`），重开回到上次位置。
  - 本科学校输入后模糊搜索并带出层次（`GET /app/api/cn-university/search`，支持简称），搜不到可手选层次。
  - 均分百分制 / 4 分制切换并显示换算结果。
  - 排名、标化、偏好可跳过，报告中提示补充。
  - 经历页「上传简历」：`POST /resume` + 轮询 `GET /resume-parse`，预填字段带「识别」标记，学生可改；解析失败不阻断手填。
  - 第 5 步「生成我的报告」→ 登录授权页（`POST /app/api/auth/wechat`）→ `POST /submit`。
- **覆盖验收**：问卷定义（JSON 驱动、改题不发版）；答题与断点；简历解析（预填、可修改、失败不影响手填）；国内高校层次表（问卷输入校名可模糊匹配）；微信登录。

### 03 报告页

- **目的**：10 秒内出报告，看完想找顾问聊。
- **主要区域（产品文档 7 个区块）**：
  1. 一句话定位（AI 生成，未返回时先显示模板句）；
  2. 竞争力画像（六维雷达，本人 vs 同层次申请者，不标分值；提示补充跳过的题）；
  3. 选校结果（冲刺 / 主攻 / 保底各 2–3 所代表校，每所一句 AI 理由；预留分享解锁条）；
  4. 最关键的 1–2 个短板（引擎差距反算 + AI 改写，说明补上后能进哪一档）；
  5. 补足后可申（未过硬门槛的项目，标明缺什么）；
  6. 下一步（主按钮预约免费顾问解读、负责顾问企微二维码、生成分享长图）；
  7. 数据说明（来源与核对日期、不代表录取承诺、AI 生成说明）。
- **关键交互**：`GET /app/api/assessment/{id}/report` 先返回结构化结果，页面轮询 AI 解读状态；`report_explainer` 失败用模板文字；预约 `POST /app/api/booking`；顾问二维码 `GET /app/api/assessment/{id}/advisor`；分享 `POST /share-image`。
- **覆盖验收**：报告（结构化 2 秒内、AI 异步 + 模板兜底、不显示百分比、含来源与免责）；加顾问企微（报告页展示负责顾问「联系我」二维码）。

### 04 分享长图

- **目的**：学生愿意转发、带来新测评的图片。
- **主要区域**：品牌头；结论标题（「英国商科硕士 · 主攻档 6 所」）；三档代表校（只有校名）；带渠道码的工作室二维码 +「扫码测测你能申哪些学校」；免责一句；图片下方「显示更多」选项（默认全不勾）；保存到相册 / 发给朋友。
- **关键交互**：服务端渲染图片（`POST /app/api/assessment/{id}/share-image`，地址存 `abr_report`）；勾选显示项后重新生成；转发卡片同样不含个人信息。
- **覆盖验收**：分享长图（默认不含姓名、本科学校、具体均分；带工作室二维码与渠道码）。

## 管理端（RuoYi-Vue3 + Element Plus：左菜单、顶栏、标签页、内容区）

### 05 首页（今日工作台简版）

- **目的**：回答「我今天先做什么」。
- **主要区域**：按角色显示的左侧菜单（顾问：首页、线索、院校库；负责人另有测评与引擎、系统）；顶栏（全局搜索、消息）；4 张数字卡（今日新线索、SLA 预警、今日待联系、本周签约）；今日待办表（已超时 › 即将超时 › 今日待联系 › 今日新线索）；本周漏斗；渠道排名。
- **关键交互**：点数字卡筛选待办；点待办行或按钮在右侧打开线索详情抽屉，不离开首页；负责人视图多「负责人」列并显示未分配、超时已升级的线索。数据来自 `GET /abroad/lead/list`、`GET /abroad/stats`。
- **覆盖验收**：角色与权限（无权限不显示入口）；SLA 提醒（界面上的可见性）；简单统计（本周测评、线索、签约与渠道排名）。

### 06 线索列表 + 详情抽屉

- **目的**：高意向线索一个不漏，每次联系都有准备。
- **主要区域**：
  - 列表：筛选（关键字、意向度、阶段、渠道、负责人、目标国家、创建时间）；快捷分组（全部 / 未分配 / SLA 预警 / 我负责的）；工具栏（批量分配、导出、列设置）；表格列：姓名 + 脱敏手机、意向度、阶段、目标、测评档位数量、渠道、负责人、最后跟进、下次联系、SLA 剩余、操作。
  - 抽屉：头部（姓名、意向度可改、阶段、负责人、SLA、来源、手机号「查看」、企微状态）；客户；测评结果（完整档位清单 + 引擎版本）；AI 线索卡片（仅内部）；跟进时间线；记跟进表单。
- **关键交互**：默认按意向度、再按 SLA 剩余排序；行内记跟进 / 改阶段 / 分配；改「流失」必填原因；改意向度必填原因；分配后企微通知；查看手机号全文记审计日志。接口：`GET /abroad/lead/list`、`GET /abroad/lead/{id}`、`PUT /abroad/lead/{id}/stage|assign|intent`、`POST /abroad/lead/{id}/follow-ups`。
- **覆盖验收**：线索列表与详情；线索自动创建（10 秒内出现、带渠道、测评摘要、意向度）；意向度（手动修改记原因）；分配；跟进与阶段（5 个阶段、流失必填原因）；SLA 提醒；角色与权限（顾问只看自己的线索）；审计日志（查看手机号全文、导出）；客户查重（重复测评归同一客户）。

### 07 项目编辑（含 AI 预填）

- **目的**：粘贴官网链接，AI 预填，录入者逐字段对照原文确认后保存。
- **主要区域**：项目头（核对日期，超过 90 天提示）+ 官网链接输入 +「AI 预填」与结果摘要；申请季切换 + 字段状态筛选；左侧字段（每行：值、状态「AI · 待确认 / 已确认 / 已修改 / 待手填」、来源 URL）；右侧原文引句对照（当前字段高亮，找不到依据的明确写「没有找到可靠来源」）；底部保存条。
- **关键交互**：`POST /abroad/program/ai-prefill`（`catalog_extractor`），30 秒内回填，显示进度、可取消；抓取失败给出原因并提示手动录入；逐字段确认 / 修改 / 清空；关键字段（均分、语言、截止日）没有来源 URL 不能保存；所有 AI 预填字段处理完前「保存」不可点；保存写入 `abr_field_source`（核对人、核对日期）。
- **覆盖验收**：院校与项目录入（按申请季录入要求）；字段来源（关键字段必须填来源 URL、显示核对日期、超 90 天标黄）；AI 预填（30 秒内、附原文引句、确认后才保存、失败有提示）。

## 企业微信侧边栏

### 08 客户信息

- **目的**：顾问在企微聊天中不切系统就能看客户、记跟进。
- **主要区域**：A 已关联：客户头部（身份、阶段、意向度、负责人、来源、SLA）、测评摘要（目标、关键背景、各档数量可展开、短板）、AI 线索卡片、记跟进表单、最近 3 条跟进 +「在管理端打开」。B 未关联：说明 + 发送测评链接（及待确认的「按手机号关联」「新建线索」）。
- **关键交互**：企微 JS-SDK 取当前外部联系人 → `GET /wecom-sidebar/api/customer`（企微身份鉴权）；记跟进保存后同步到管理端时间线并停止 SLA 计时；学生扫顾问「联系我」码时由 `/callback/wecom` 自动关联。
- **覆盖验收**：企微侧边栏（显示测评结果、线索卡片，可记跟进）；加顾问企微（添加后自动关联到客户）。

## 需要创始人确认的问题

每条后面是线框图里先采用的默认做法。

1. **测评人数显示口径（01）**：默认按完成测评累计人数，满 100 人才显示，随问卷定义接口返回。
2. **落地页报告样例（01）**：默认用模糊处理的示例报告，标注「示例」，不用真实学生数据。
3. **雷达图六维与对比基线（03）**：默认院校层次、均分、专业相关度、语言、科研、实习；冷启动期基线用顾问设定的同层次典型值。
4. **短板是否写综合分差距（03）**：默认不写分数，只写「补上后可从冲刺进入主攻」。
5. **分享解锁 1a 是否做（03、04）**：默认不做，只预留位置（1a 功能点中没有）。
6. **长图二维码生成方式（04）**：默认统一「报告分享」渠道码 + 分享人测评 ID 参数。
7. **长图可选显示项（04）**：默认只允许昵称、院校层次（不写校名）、均分区间，全部默认不勾。
8. **每档展示数量（03）**：默认冲刺 2、主攻 3、保底 2，并显示各档总数。
9. **顾问端是否显示录取可能性或综合分（06、08）**：默认不显示，与学生端一样只显示档位。
10. **首页统计的数据范围（05）**：默认顾问只看自己的，负责人看全部。
11. **首页是否放 AI 助手和「AI 待确认」（05）**：默认 1a 不放。
12. **抽屉的「下一步建议」「首访准备」（06）**：默认 1a 不做。
13. **顾问能否看手机号全文（06）**：默认可看自己负责线索的全文，每次记审计日志；导出只限负责人。
14. **改意向度的原因格式（06）**：默认下拉（已确认意向 / 入学时间变化 / 预算不匹配 / 其他）+ 选填备注。
15. **AI 预填等待方式与批量确认（07）**：默认页面内等待并显示进度；必须逐字段确认，不提供一键全部确认。
16. **侧边栏记跟进接口与未关联时的操作（08）**：默认新增 `/wecom-sidebar/api/follow-ups`；1a 只做「发送测评链接」，关联与新建放到 1b。
17. **侧边栏是否显示手机号（08）**：默认不显示。
18. **品牌素材（全部）**：工作室名称、Logo、品牌色、二维码何时提供；开发期用「XX 留学工作室」占位，按初始化向导存参数表。
19. **顾问解读时长（03）**：产品文档写「免费 20 分钟」，冷启动文档写体验官「免费 30 分钟」；默认报告页写 20 分钟。
20. **落地页是否写明切入人群（01、02）**：默认写明英国、澳洲、新加坡授课型硕士；其他方向仍可答题，引擎未覆盖的组合在报告中提示「暂由顾问人工评估」并引导预约。
