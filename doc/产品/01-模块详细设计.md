# 模块详细设计

本页展开主文档里的五个模块：文书挖掘、院校要求库、信息更新、录取案例库、内容中心。

## 苏格拉底式文书挖掘：目标与原则

文书挖掘的产出不是文章，而是三样东西：**一份结构化的素材库、2–3 条候选主线、每所学校的大纲**。正文由学生写，AI 只提问、整理和批注。

**对话原则**

1. **一次只问一个问题：** 问题短、具体、好回答；不一次扔出五个问题。
2. **只问不答：** 不替学生回答，不给「参考答案」，不替学生编经历；学生说「你帮我想一个」时反问他自己的经历。
3. **追问到具体：** 目标是场景、动作、数字、对话、当时的想法；听到「热爱」「受益匪浅」「提升了能力」这类空话就追问。
4. **保留原话：** 素材卡片里保存学生的原话（中文或英文），大纲引用原话而不是改写后的「漂亮话」。
5. **让学生做选择：** 主线、事例取舍由学生选，AI 只给选项和理由。
6. **尊重边界：** 家庭变故、健康、心理等敏感话题可以跳过；识别到情绪困扰时停止追问并提醒顾问。
7. **可中断、可续聊：** 每次 20–30 分钟，系统记住进度，下次从断点继续。

**边界（产品层面强制）**：AI 不输出可直接提交的段落或整篇；批注只针对学生已写的文字；每一版文书都留存，可证明是学生自己写的。

## 对话流程

一位学生的文书从准备到定稿走 11 步；前七步是挖掘，通常分 3–5 次对话完成。

> 图：文书挖掘流程 · 11 步，3 个回路（图在在线文档中查看：https://claude.ai/code/artifact/3f423242-8dd1-4136-99ec-c924c5bddfc5）

三个回路：每段经历要追问到素材卡完整度 ≥ 80% 才继续；题目映射发现某校题目缺素材时，回到深挖针对性追问；学生每次改稿后再批注，直到文案老师终审通过。

| 步骤 | 谁主导 | 产出 |
| --- | --- | --- |
| 准备 | 系统 | 读取学生档案、定校清单、各校文书题目，确定要写的文书类型（PS / SOP / Why School / Diversity 等） |
| 破冰与动机 | AI 提问 | 专业动机的第一版原话 |
| 经历盘点 | AI 提问 + 档案预填 | 经历时间线，每段一张空白素材卡 |
| 逐段深挖 | AI 提问 | 完整的素材卡（按重要性优先挖 3–5 段） |
| 主题提炼 | 学生选择 | AI 给出 2–3 条候选主线及理由，学生选一条并说明原因 |
| 题目映射 | 系统 + 文案老师 | 每校每题用哪些素材、缺什么 |
| 大纲 | 学生确认 | 每段要点 + 对应素材卡 + 学生原话 |
| 学生写作 → AI 批注 → 终审 | 学生写，AI 与文案老师批 | 各校定稿及全部版本记录 |

## 提问框架

每一段关键经历都按「追问五层」从浅到深挖，哪一层答得空泛就停在哪一层继续问。

| 层 | 要拿到什么 | 示例问题 |
| --- | --- | --- |
| 1 事实 | 时间、地点、你的角色、发生了什么 | “这个项目是什么时候、和谁一起做的？你负责哪一块？” |
| 2 行动 | 你具体做了什么（不是「我们」）、结果和数字 | “你自己做的第一步是什么？最后数据提升了多少？” |
| 3 困难与选择 | 卡住的地方、当时有哪些选择、为什么选了这个 | “最难的一天发生了什么？当时你想过放弃吗？” |
| 4 反思与改变 | 这件事让你对自己或专业的看法有什么变化 | “做完之后，你对什么事的看法跟以前不一样了？” |
| 5 连接 | 和目标专业、未来规划、这所学校的关系 | “这段经历和你想读的这个项目有什么关系？” |

**问题类型**（引擎按场景选用）

| 类型 | 什么时候用 | 示例 |
| --- | --- | --- |
| 澄清 | 回答有歧义 | “你说的「优化」具体是改了什么？” |
| 具体化 | 出现空泛词 | “能说一个让你觉得「热爱」的具体瞬间吗？” |
| 动机 | 只说了做什么，没说为什么 | “当时是什么让你想试试这个方向？” |
| 反事实 | 想确认选择的分量 | “如果当时没做这个决定，结果会怎样？” |
| 对比 | 找独特性 | “同组的同学和你的做法有什么不一样？” |
| 感受 | 叙述缺少人的温度 | “那一刻你心里在想什么？” |
| 未来 | 做 Why School / 职业规划 | “毕业五年后，你希望自己在做什么？” |

**空泛表达识别**：维护一份「空话词表」（热爱、激发了兴趣、受益匪浅、提升了综合能力、passionate、broaden my horizons 等），再加大模型判断「这句话有没有可验证的细节」；命中就触发「具体化」追问。词表由文案老师维护，可按租户配置。

## 对话引擎实现

引擎 = **规则状态机控制「问到哪一步」+ 大模型负责「怎么问、听懂了什么」**。不让大模型自由发挥整场对话，否则容易跑题、代答或漏问。

**每一轮的处理**

1. **理解：** 大模型把学生这轮回答抽取成结构化字段，写入当前素材卡片，并保留原话。
2. **打分：** 计算卡片完整度（下表），并检查空话、矛盾（与前面说的或档案不一致）。
3. **决策（规则）：** 完整度不足 → 针对最缺的字段追问；同一字段已追问 3 次 → 标记「待顾问补充」并跳过；完整 → 下一段经历或下一阶段。
4. **生成问题：** 大模型按指定的问题类型和字段生成一个问题，经输出检查（只有一个问号、不含代答、不含范文）后发出。

**素材卡片结构**

| 字段 | 说明 | 计入完整度 |
| --- | --- | --- |
| 标题、时间、类型 | 类型：科研 / 实习 / 项目 / 竞赛 / 志愿 / 个人经历 | 是 |
| 角色与情境 | 你是谁、在什么场景里 | 是 |
| 行动 | 你本人做了什么 | 是（权重最高） |
| 结果 | 最好有数字或可验证的产出 | 是 |
| 困难与选择 | 卡住的地方、做过的取舍 | 是 |
| 反思 | 看法的改变 | 是 |
| 能力与特质标签 | 如好奇心、韧性、领导力（AI 建议，学生确认） | 否 |
| 与专业 / 学校的连接 | 可用于哪些题目 | 否 |
| 原话引用 | 学生最有个人色彩的 1–3 句原话 | 否 |
| 来源与版本 | 哪次对话、哪一轮、是否经顾问确认 | 否 |

完整度 = 六个计入字段的加权得分（空话算未填）；≥ 80% 视为可用素材。权重和阈值可配置。

**防代写控制**

- 挖掘阶段：输出检查拦截任何「示范回答」或超过一句的陈述。
- 大纲阶段：每段只给「这段要说明什么 + 用哪张素材卡 + 学生原话」，不生成成段文字。
- 批注阶段：以提问和说明为主；句子级的语言修改建议一次只针对一句，并标注改动。
- 全程版本留存：学生每次保存的稿子、AI 批注、文案老师修改分开记录。

**人工介入**：文案老师可以实时查看对话、插入自己的问题、把某张素材卡标为重点或不用；引擎遇到敏感话题、连续 3 轮没有新信息、学生要求代写时自动通知文案老师。

**效果评估**

| 指标 | 定义 |
| --- | --- |
| 素材产出 | 每位学生得到的可用素材卡数、平均完整度 |
| 文案老师评价 | 对素材库和大纲的 1–5 分评分；大纲被采用比例 |
| 省下的时间 | 文案老师素材访谈耗时上线前后对比 |
| 学生体验 | 对话完成率、中途放弃的阶段、满意度 |
| 安全 | 拦截的代写请求数、输出检查拦截次数 |

对话记录（经学生同意、脱敏后）和文案老师的修改回流到 AI 平台的评测集，用于改进问题生成。

## 院校要求库

院校要求库是整个平台的「事实来源」：选校引擎、智能问答、申请清单都只从这里取数。**每个字段都带来源 URL、核对日期和适用申请季**，没有来源的值不入库。

**数据模型**

| 实体 | 主要字段 |
| --- | --- |
| 院校 | 中英文名、国家城市、类型、各榜单名次（注明榜单和年份）、是否在教育部涉外监管信息网的认可名单内 |
| 项目 | 所属学院、学位、学制、入学季、学费、授课方式、内部学科分类、是否面试、美国 STEM 标识 |
| 学术要求 | 接受的本科专业、先修课、按中国院校层次的均分要求、标化要求、工作经验 |
| 语言要求 | 雅思 / 托福 / 多邻国等总分与小分、是否接受课前语言、豁免条件 |
| 材料与文书 | 推荐信数量与形式、文书题目原文与字数、简历、作品集、视频面试 |
| 申请轮次 | 开放日、各轮截止日（含时区）、申请费、滚动录取标识 |
| 官方统计 | 录取率、班级画像、就业报告（仅收录官方发布的） |
| 字段溯源 | 每个值的来源 URL、抓取时间、核对人、核对日期、适用申请季、历史版本 |

**信息来源与可信度**

| 来源 | 提供什么 | 可信度 | 获取方式 |
| --- | --- | --- | --- |
| 项目官网（招生页、项目页、FAQ） | 几乎全部要求和截止日 | 最高 | 定期抓取 + AI 抽取 + 人工核对 |
| 学校招生办「国际学生 / 按国家要求」页 | 语言总要求、中国院校名单与均分要求 | 最高 | 同上 |
| 官方 PDF（招生手册、班级画像） | 统计数据、详细要求 | 高 | 下载 + 文档解析 |
| 申请系统（如 UCAS、Common App 的院校要求页） | 本科申请要求与截止日 | 高 | 人工为主，按其使用条款处理 |
| 官方统计（如美国高校的 Common Data Set） | 本科录取率、标化分布 | 高 | 每年人工导入 |
| 大学排名（QS、THE、US News、软科） | 名次 | — | 仅存名次并注明来源年份与存档，遵守各榜单使用条款；robots 允许的自动低频抓取，禁止抓取的每年由员工上传官方页面另存件、学校官网名次新闻交叉核对（《开发计划·榜单获取》） |
| 美国教育部 College Scorecard / IPEDS | 美国院校官方名称、所在地、官网、IPEDS 编号 | 最高 | 官方开放接口与数据文件（公有领域），自动获取并存档 |
| 教育部教育涉外监管信息网 | 外国高校是否在认可名单内（影响回国学历认证） | 最高 | 定期人工核对 |
| 学校邮件回复、招生宣讲记录 | 官网没写的细则 | 中 | 顾问录入，标注「非公开渠道」和日期 |
| 论坛、社交媒体 | 传闻、经验 | 低 | 不入库，只作为「需要去核对」的线索 |

**覆盖策略**：先覆盖主做国家的常申项目（几百个），再按「被测评命中、被定校的次数」排优先级扩充；没收录的项目在测评里不出现，而不是用大模型临时估计。

**抓取合规**：只抓公开页面，遵守 robots.txt 和网站条款，低频访问；不登录、不绕过限制；对外只展示提取的事实字段和链接，不转载页面全文。为便于核对，抓取的原文作为内部存档保存（只在管理后台查看），超过 2 年自动清理，当前在用值引用的存档保留。

## 信息更新

更新的原则是**机器发现变化、人确认发布、系统通知受影响的人**。大模型只用于把网页抽取成字段，不直接改库。

**更新流程**

1. **监控清单：** 每个项目登记 1–5 个「监控页面」（项目页、要求页、截止日页、文书题目页、语言要求页）。
2. **定时抓取：** 按下表频率抓取；先比对页面正文的指纹，没变就只更新「最后检查时间」，不调用大模型。
3. **字段抽取：** 页面变了才用大模型按固定字段结构抽取，并要求每个值附上原文引句。
4. **字段级比对：** 与库中现值逐字段对比，生成「变更单」（旧值 → 新值 + 原文引句 + 页面快照）。布局变化、日期更新等无实质变化的自动忽略。
5. **人工审核：** 数据运营在审核台对照原文确认、修改或驳回；截止日、语言分、均分要求类变更标为高优先级。
6. **发布与版本：** 确认后写入新版本（旧版本保留），并发出「项目要求变更」事件。
7. **通知受影响的人：** 定校清单里有这个项目的学生及其顾问收到提醒；影响选校结果的变更触发重算测评档位；内容中心收到一条「新政」选题。

**抓取频率**

| 时期 | 频率 | 重点 |
| --- | --- | --- |
| 新申请季开放前后（通常每年秋季） | 每天 | 新一季要求、文书题目、截止日 |
| 申请季中 | 每周 2–3 次 | 截止日变更、轮次关闭 |
| 非申请季 | 每周一次 | 语言、中国院校名单等要求 |

**新鲜度管理**：每条记录显示核对日期；超过 90 天未核对自动进入「待复核」队列；抓取失败（页面改版、链接失效）当天告警，由数据运营重新登记页面。对外展示时附「以学校官网为准」和官网链接。

**人力估算**：核心成本在审核；前期几百个项目可由顾问兼管，扩到上千个项目后需要专职数据运营。

## 录取案例库

案例库是选校算法和内容营销共同的数据来源，也是最难被竞争对手复制的资产。核心要求是**真实、结构化、可追溯、不暴露个人**。

**案例来源**

| 来源 | 怎么拿到 | 核验等级 | 用途 |
| --- | --- | --- | --- |
| 自己签约的学生 | 服务流程第 10 步必填：每个项目的录取 / 拒绝 / 候补 + offer 截图；合同里约定授权脱敏使用 | A：顾问核验 offer | 算法训练 + 宣传（另需宣传授权） |
| 测评用户自愿回填 | 放榜季推送「回填结果，拿一份择校建议」；上传 offer 截图由 AI 识别 + 人工抽检 | B：有截图 / C：只有自报 | 算法训练（C 级降权） |
| 其他租户（产品化后） | 租户自愿加入「数据共建」，只贡献脱敏后的统计，换取平台默认参考线更准 | 按各租户等级 | 平台级参考线（只用聚合值） |
| 公开论坛、社交媒体晒 offer | 人工浏览参考，不批量抓取 | D：未核验 | 仅作顾问参考，不进算法 |

**案例结构**：申请季、目标国家与项目、结果（录取 / 拒绝 / 候补 / 撤申）、奖学金、本科院校层次与专业、均分、语言与标化、科研 / 实习 / 竞赛概要（与测评同一套维度）、核验等级、来源、授权范围。**拒绝和候补与录取同样重要**，只记录录取会让算法系统性高估。

**脱敏规则**

- 入库即拆分：身份信息留在学生档案，案例库只存背景特征和结果，只有授权角色能关联回档案。
- 泛化：本科院校对外只显示层次（如「985」），均分显示区间（如 85–88）。
- 小样本保护：同一组合（院校层次 + 专业 + 录取项目 + 申请季）少于 5 条时，对外统计不显示，宣传需单独授权。
- 宣传授权与算法使用授权分开勾选，可随时撤回。

**质量控制**：同一学生同一项目去重；与项目库不匹配的项目名由人工归一；明显异常值（均分远低于要求却录取）进入复核；每季输出案例覆盖报告（哪些国家、专业样本不足）。

## 内容中心

内容中心把平台里已有的数据（政策变更、录取案例、测评洞察）变成引流内容，并追踪每条内容带来了多少测评和签约。

**选题来源（自动进选题池）**

| 来源 | 触发方式 | 内容示例 |
| --- | --- | --- |
| 院校要求变更 | 「项目要求变更」事件 | 「XX 大学今年语言要求上调了」 |
| 新增录取案例 | 有宣传授权的案例入库 | 「双非均分 85，拿到 XX 大学 offer 的三个关键」 |
| 测评数据洞察 | 每月汇总测评数据 | 「本月 1,000 位测评同学最大的短板是什么」（仅用聚合数据） |
| 用户高频问题 | 咨询、智能问答、评论区里的问题聚类 | 「跨专业申请商科，先修课怎么补」 |
| 申请季节点 | 内置年度日历 | 开放申请、截止前提醒、放榜、签证高峰 |

**生产流程**

1. **选题：** 市场从选题池挑选并排进内容日历。
2. **生成：** 内容 Agent 按平台模板（小红书图文、公众号长文、视频口播稿、朋友圈短文）生成初稿；事实只从院校库和案例库取，并附引用。
3. **合规检查：** 自动检查广告违禁词和录取承诺、案例是否有宣传授权、是否可识别到个人。
4. **人工审核：** 顾问核事实，市场改风格；所有内容都要人工确认才能发布。
5. **发布：** 有开放接口的平台（如公众号）从系统直接发布；其余平台导出稿件和图片，由人工发布后回填链接。
6. **归因：** 每条内容生成独立的测评入口（带参二维码 / 小程序路径参数 / 短链），系统统计「内容 → 测评 → 预约 → 签约」；浏览和互动数据手工或按平台允许的方式回填。

**反馈闭环**：每月输出「哪类选题、哪个平台、哪种形式带来签约」的排行，调整内容日历；表现好的内容结构沉淀为新模板。

各平台的开放接口、数据获取方式和营销规则变化较快，接入前需逐一核对各平台当前的开放能力和规则。
