## 背景与目标

**定位：一家新成立、人数在 10 人以内的创业型留学工作室的 AI 经营平台。** 先在自己工作室内部使用，让少数人做出大机构的获客和服务能力；打磨成熟后，再以「标准产品 + 定制交付」输出给同类的小型留学工作室和公司。创业期的硬约束是**人少、钱紧、时间短**：只做能直接带来签约或省下人力的功能，其余保留架构、推迟建设。业务目标的优先级不变：先获客，再提效，验证后再对外输出。

| 优先级 | 目标 | 产品要做到 | 怎么算成功 |
| --- | --- | --- | --- |
| 1 | 获客引流 | 一个学生愿意主动去用、愿意转发的免费选校测评，测完自然想找顾问聊 | 每月稳定产生合格线索，线索到签约转化率不低于其他渠道 |
| 2 | 内部提效 | 选校方案、文书素材挖掘、申请进度、家长沟通、内容生产都有 AI 先做初稿 | 单个顾问可服务学生数明显上升，客户满意度不降 |
| 3 | 对外输出与定制 | 内部用顺后，以「标准产品 + 定制交付」输出给其他中小留学公司；测评组件也可单独给语培机构和国际学校 | 见「分阶段路线」的门槛 |

**设计原则**

1. **一套核心、多种部署：** 每条业务数据都带租户和组织归属；同一套代码既可给客户独立部署（定制客户的主要方式），也可多客户共用（SaaS）。定制只通过配置和扩展点实现，不为每个客户分叉一套代码，保证所有客户都能升级。
2. **配置优于定制：** 服务包、流程节点、分配规则、算法权重、报告模板、审核策略都可配置，新客户上线不改代码。
3. **功能开关分期启用：** 按租户和套餐开关模块，工作室前期只开获客、CRM 和选校，其余模块就绪后开启。
4. **AI 可控可审计：** 所有 AI 输出可追溯到模型、提示词版本和依据；影响学生决策的输出必须经人工确认。
5. **数据是资产：** 线索、服务过程、录取结果全量结构化沉淀，支撑算法、经营分析和内容生产。

**工作室的天然优势：** 顾问就是产品的第一批用户和审核者，每个签约学生的录取结果都会回流成自己的案例库，这是选校算法最值钱的数据。

## 产品理念与核心优势

**一句话价值主张：用自己的录取数据做出可信的选校，用可信的选校带来客户，用 AI 把每个顾问的服务能力翻倍——且每一条建议都有人负责、有据可查。**

**四个核心优势**

1. **可信的选校引擎，而不是「会聊天的 AI」。** 打分由确定性规则和统计模型完成，同一份背景每次结果一致；每个结论都能追到官网要求和录取案例。通用大模型会编造院校信息，普通测评工具是黑箱。
2. **越用越准的数据飞轮。** 每个签约学生的录取 / 拒绝结果、顾问的每次调档都反哺算法；案例脱敏后又变成引流内容。这是竞争对手买不到、追不上的资产。
3. **获客到交付一体。** 同一份学生数据从测评一直用到入学：测评的背景就是档案，档案变化自动重算选校，录取结果自动进案例库。市面上的 CRM、测评工具、文书工具各管一段，数据断在中间。
4. **可审计的人机协同。** AI 做初稿、人拍板；文书只挖掘不代写；每条 AI 输出都能查到模型、依据和审核人。对家长是信任，对机构是合规和学术诚信的保障。

**与替代方案对比**

| 对比项 | 本产品 | 通用大模型聊天 | 选校测评工具 | 留学机构 CRM | 人工 + Excel |
| --- | --- | --- | --- | --- | --- |
| 院校信息可信 | 官网来源 + 核对日期 | 可能过时或编造 | 视厂商而定 | 一般不含 | 靠顾问记忆 |
| 选校依据 | 自有案例 + 可解释引擎 | 无 | 多为黑箱 | 无 | 顾问经验 |
| 获客能力 | 测评 + 内容 + 归因 | 无 | 有（厂商自己的流量） | 只管线索 | 无 |
| 交付提效 | 方案、文书、申请、家长沟通 | 零散帮忙 | 无 | 记录为主 | 无 |
| 合规与审计 | 全程留痕 | 无 | 一般 | 部分 | 无 |

具体产品的调研见 竞品调研；对外使用前仍需逐条核实。

## 创业期取舍

创业期的原则：**只自建形成壁垒的部分（测评引擎、院校与案例数据、文书挖掘），其余尽量用现成工具；公司级功能保留数据结构，等有需要再建。**

| 能力 | 创业期做法 | 理由 | 何时再自建 / 升级 |
| --- | --- | --- | --- |
| 选校测评引擎 + 报告 | 自建 | 获客入口和核心壁垒 | 阶段 1a 立即做 |
| 院校库、录取案例库 | 自建数据结构，先人工 + AI 录入 | 越用越值钱的数据资产 | 阶段 1a 立即做 |
| 线索看板（轻量 CRM） | 自建简版 | 与测评打通是关键，现成 CRM 接不起来 | 阶段 1a |
| 文书挖掘 Agent | 自建 | 差异化与合规卖点 | 阶段 1b |
| 客户沟通 | 企业微信（现成） | 免开发，客户和家长都在微信 | 不自建，只做侧边栏对接 |
| 电子合同 | 第三方电子签服务 | 合规、按份付费 | 签约量大后再接入系统 |
| 收款与记账 | 微信支付 / 对公转账 + 记账软件 | 创业期合同少，不值得建财务中心 | 对外输出时 |
| 内部 SOP 与知识 | 现成在线文档 | 只是文字资料 | 沉淀成型后导入 AI 知识库 |
| 内容发布 | 各平台原生后台 + 自建内容助手生成稿件 | 平台开放接口有限 | 平台开放后 |
| 经营看板 | 先做一页简单统计（线索、测评、签约、渠道） | 创始人最关心的就是这几个数 | 阶段二 |
| 大模型 | 调用已备案的大模型 API，按量付费 | 不自建、不微调 | 不自建 |
| 多校区、多级审批、租户管理、等保 | 先不做，只保留数据结构（如 tenant_id） | 创业期用不上 | 对外输出前 |

**创业期的开发方式**：系统主要由 AI 编写；创始人负责写需求和验收，顾问当种子用户和数据录入者。需求和验收必须由工作室自己把握，安全相关代码仍需人工评审（见「技术架构·开发方式」）。

## 组织、角色与权限

组织模型按「租户 → 公司 → 校区/分公司 → 团队 → 员工」五级设计，创业期（10 人以内）只用一个团队，一人兼多岗；典型配置为创始人（兼咨询与规划）、顾问 2–3 人、文案 1–2 人、申请 / 签证 1 人、新媒体 1 人。下表是公司规模后的完整角色，创业期用「上线与使用便捷」里的工作室模式。

| 岗位角色 | 主要职责 | 主要使用模块 | 默认数据范围 |
| --- | --- | --- | --- |
| 市场 / 新媒体 | 内容生产、渠道投放、活动 | 内容中心、活动、渠道分析 | 本公司营销数据（不含学生隐私） |
| 咨询 / 销售顾问 | 线索跟进、首访、签约 | CRM、选校方案、合同 | 本人私海 + 公海 |
| 规划顾问 | 选校定位、背景规划 | 选校工作台、规划 | 分配给本人的学生 |
| 文案老师 | 文书挖掘、修改、定稿 | 文书中心 | 分配给本人的文书任务 |
| 申请专员 | 网申填报、递交、结果跟踪 | 申请中心 | 分配给本人的申请 |
| 签证 / 行前专员 | 签证材料、行前服务 | 签证中心 | 分配给本人的学生 |
| 客服 / 班主任 | 家长沟通、投诉、满意度 | 服务工单、消息中心 | 负责的学生（只读业务材料） |
| 财务 | 收款、退款、开票、提成 | 财务中心 | 本公司合同与收款 |
| 团队主管 / 校区负责人 | 分配、质检、业绩 | 全部（本级数据） | 本团队 / 本校区 |
| 公司管理层 | 经营决策 | 经营看板 | 全公司 |
| 学生 / 家长 | 测评、提交材料、查看进度 | 学生端 / 家长端 | 本人（家长经学生授权） |
| 平台运营（我方） | 租户开通、院校数据、模型与算法 | 平台运营后台 | 不可看租户学生数据，排障需租户临时授权 |

**权限模型**

- **功能权限：** RBAC，角色 → 菜单 / 按钮 / 接口；租户可自建角色。
- **数据权限：** 本人 / 本团队 / 本校区 / 全公司四档，叠加「分配关系」（学生只对服务小组成员可见）。
- **字段权限：** 手机号、证件号、合同金额等敏感字段按角色脱敏显示，导出需审批并留痕。
- **离职交接：** 员工停用时其线索、学生、任务一键转交，防止顾问带走客户。

## 端到端业务流程

一个学生从第一次测评到入学要经过 12 个阶段、约 6 个岗位；每个阶段在系统里都是一个状态节点，有负责人、时限和产出物。SLA 为默认值，租户可配置。

| # | 阶段 | 负责岗位 | 产出 / 状态节点 | 默认 SLA | AI 辅助 |
| --- | --- | --- | --- | --- | --- |
| 1 | 获客 | 市场 | 线索入库（带渠道） | — | 内容生成、测评、意向度评分 |
| 2 | 线索分配与首次联系 | 咨询顾问 | 分配记录、首联记录 | A 类 2 小时内 | 线索卡片、开场话题 |
| 3 | 首访与方案 | 咨询顾问 + 规划顾问 | 首访纪要、初步选校方案 | 首访后 24 小时内出方案 | 会议纪要、方案初稿 |
| 4 | 签约与收款 | 咨询顾问 + 财务 | 电子合同、收款记录 | — | 合同条款生成与核对 |
| 5 | 服务启动 | 团队主管 | 服务小组、服务计划、学生档案 | 签约后 3 天内 | 按服务包自动生成任务计划 |
| 6 | 背景提升 | 规划顾问 | 提升计划与打卡 | 按计划 | 差距分析、提升建议 |
| 7 | 定校 | 规划顾问 + 学生家长 | 定校清单（学生确认） | 申请开放前 | 选校引擎、项目对比 |
| 8 | 文书 | 文案老师 | 素材库、各校文书定稿 | 每轮修改 3 个工作日 | 素材挖掘、大纲、批注 |
| 9 | 网申递交 | 申请专员 | 递交截图、推荐信状态 | 截止前 7 天完成 | 材料清单、表格核对 |
| 10 | 录取与择校 | 规划顾问 | 录取结果录入、择校建议 | 结果出后 2 天内录入 | offer 对比、面试模拟 |
| 11 | 签证 | 签证专员 | 签证材料、递交与结果 | 按国家 | 材料清单、面签模拟 |
| 12 | 行前与结案 | 签证专员 + 客服 | 行前清单、满意度、转介绍 | 入学前 | 行前问答、案例脱敏成内容 |

## 获客闭环

免费选校测评是整个产品的钩子：内容把人引来测评，报告把人引到顾问，签约学生的录取结果又变成新的内容和更准的算法。

> 图：获客闭环 · 8 步，3 个回路（图在在线文档中查看：https://claude.ai/code/artifact/3f423242-8dd1-4136-99ec-c924c5bddfc5）

三个回路决定增长：报告分享带来新测评；不急的线索进入成长计划定期重测；录取案例脱敏后成为下一批引流内容。

**各渠道打法**

| 渠道 | 内容形式 | 挂测评的方式 |
| --- | --- | --- |
| 小红书 | 「双非 85 分能申哪些英国学校」类干货、录取案例卡片 | 评论区 / 主页引导「测测你的定位」 |
| 视频号 / 抖音 | 顾问口播：院校新政、选校误区、案例拆解 | 视频号直接跳小程序 |
| 公众号 | 年度录取报告、国家对比长文 | 文末小程序卡片 |
| 线下讲座 / 高校社群 | 留学规划讲座 | 现场扫码测评，讲座后逐一解读 |
| 老客户转介绍 | 已签约学生分享测评 | 带老客户标识的二维码，签约后给推荐奖励 |

每个入口都带渠道参数，线索看板里能看到哪个渠道、哪条内容真正带来了签约。

## 智能选校测评算法

算法分六步：采集背景 → 维度打分 → 硬门槛筛选 → 估计录取可能性 → 分冲/稳/保并按偏好排序 → 生成差距和提升建议。**打分和分档由规则与统计模型完成，大模型只负责解析材料和写解释**，这样同一份背景每次测结果一致，也不会编造院校信息。

### 1. 输入维度

学生 3–5 分钟填完，也可以直接上传简历和成绩单由 AI 解析后确认。

| 类别 | 维度 | 采集方式 | 归一化为 0–100 子分 |
| --- | --- | --- | --- |
| 学术 | 本科院校层次 | 选择或解析 | C9 / 985 / 211 / 双一流 / 双非 / 海本分档，并按目标国家院校的「中国院校认可名单」得到该校的门槛均分 |
| 学术 | GPA / 均分 | 填写或成绩单解析 | 统一换算为百分制，再与「院校层次对应的门槛均分」做差值 |
| 学术 | 专业相关度 | 本科专业 + 核心课程 | 本专业 / 相近 / 跨专业三档；缺先修课记为风险项 |
| 学术 | 排名 | 选填 | 前 10% / 30% / 其他 |
| 语言 | 雅思 / 托福 / 多邻国 | 填写 | 按官方对照表统一到雅思尺度；未考的按「预估分 + 待考」处理 |
| 标化 | GRE / GMAT | 选填 | 相对目标专业录取中位数的位置；不要求的项目不计入 |
| 软背景 | 科研 | 条目 + 级别 | 核心期刊 / 会议 / 课题组 / 无，按与目标专业相关度加权 |
| 软背景 | 实习 / 工作 | 条目 + 公司层级 + 时长 | 头部公司 / 一般公司，相关 / 不相关，累计月数 |
| 软背景 | 竞赛、项目、证书 | 条目 + 级别 | 国际 / 国家 / 省级 / 校级 |
| 偏好 | 国家地区、预算、排名 vs 就业、城市、学制 | 填写 | 不进竞争力分，只用于筛选和排序 |

### 2. 综合竞争力分

每个学生对每个「国家 × 学位 × 专业大类」组合算一个综合竞争力分 C，权重随组合不同：

```latex
C = \sum_{k} w_{k}^{(\text{国家, 学位, 专业})} \cdot s_k
```

sₖ 是第 k 个维度的 0–100 子分，wₖ 是权重。初始权重由顾问按经验设定，下表为示意：

| 申请类型 | 院校层次 + GPA | 专业相关度 | 标化 | 科研 | 实习 / 工作 | 其他软背景 |
| --- | --- | --- | --- | --- | --- | --- |
| 英国授课型硕士 | 65% | 15% | 0% | 5% | 10% | 5% |
| 香港 / 新加坡硕士 | 55% | 15% | 5% | 10% | 10% | 5% |
| 美国商科硕士 | 35% | 10% | 20% | 5% | 25% | 5% |
| 美国理工科硕士 | 40% | 15% | 10% | 20% | 10% | 5% |

语言成绩不进权重，只做硬门槛（下一步）：多数项目对语言是「达标即可」，进权重会高估高分学生。

### 3. 硬门槛筛选

先按项目官网要求过滤，不达标的项目不进入冲/稳/保，而是单列为「补足后可申」：

- 院校层次对应的最低均分（如英国院校对不同层次中国本科的均分要求）
- 语言总分和小分；允许课前语言的项目单独标注
- 先修课、工作年限、是否接受跨专业

### 4. 录取可能性估计

每个项目 j 有一条「录取参考线」Tⱼ（录取者的典型综合分）和一个稳定度参数 aⱼ（项目录取越标准化 a 越大）。学生 i 的录取可能性：

```latex
P_{ij} = \frac{1}{1 + e^{-a_j (C_i - T_j)}}
```

- 冲刺：P < 35%；主攻：35%–70%；保底：P > 70%（阈值可调）。
- 对外只展示档位，**不展示具体百分比**：一是冷启动期数字不准，二是避免被理解为录取承诺。
- Tⱼ 的来源按可信度从高到低：工作室自己的录取案例 → 项目官方公布的录取统计 → 顾问按经验给的难度分（五档）。每条 Tⱼ 标明来源。

### 5. 冲/稳/保方案与排序

- 每档内按「偏好匹配分」排序：预算、排名 vs 就业、城市、学制，各项由学生自己选重要程度。
- 默认组合 2 冲 + 4 稳 + 2 保，约束：总预算不超、至少一所保底在学生首选国家。

### 6. 差距与提升建议（反向指引）

对学生最想要的冲刺校，反算「让 P 进入主攻档」需要的最小提升，只在学生还能改变的维度里找（语言、标化、科研、实习），并按剩余时间判断是否现实。例：「距主攻档差约 6 分；GRE 从 315 到 325 可补 4 分，增加一段 3 个月相关实习可补 3 分」。这部分正好是顾问服务的切入点。

### 7. 冷启动与自我校准

1. **第一个申请季（规则版）：** 权重、Tⱼ、aⱼ 都由顾问设定，先覆盖工作室主做的 2–3 个国家、约 200–300 个常申项目。
2. **顾问修正即训练信号：** 顾问在工作台里把某校从「稳」改到「冲」时记录原因，用于调整 Tⱼ。
3. **录取结果回流：** 每个学生每个项目的录取/拒绝/候补都记入案例库；单个国家积累到约 200 条结果后，用逻辑回归重新拟合权重和 Tⱼ。
4. **校准检查：** 每季对比各档实际录取率（如「保底」档实际录取率应 > 70%），偏差大的国家或专业单独调整。

上述权重、阈值和样本量都是初始假设，需由顾问按实际经验调整；英国院校的中国院校认可名单等要以各校官网最新公布为准。

### 8. 多国家适配

主做方向为美国、英国、澳洲、新加坡、中国香港、日本；韩国、德国保留。各国录取逻辑差异很大，**不能用一套权重套所有国家**：引擎按「国家 × 学位」分别配置权重和硬门槛，并增加「申请路径」维度。

| 国家 | 录取逻辑（概要） | 引擎需要的特殊处理 |
| --- | --- | --- |
| 美国 | 本科综合评估（文书、活动、标化政策因校而异）；硕士看 GPA、标化、科研实习 | 软背景权重高、不确定性大（a 值小），档位偏保守；本科与研究生分开建模 |
| 英国 | 授课型硕士重本科院校层次 + 均分，不少学校对中国院校有分层均分要求；多为滚动录取 | 层次均分表为核心硬门槛；提示递交时机 |
| 澳洲 | 与英国类似，按院校层次给均分要求，标准化程度较高 | 规则版即可较准，适合作为保底国家 |
| 新加坡 | 重院校背景与 GPA，名额少、竞争激烈 | 参考线高、保底档少，提示与其他国家混申 |
| 中国香港 | 授课型硕士重院校背景与 GPA，学制多为 1 年；多数项目分轮次录取、先到先得；常与英、新混申 | 参考线高；提示尽早递交与各轮截止日；保底不足时提示混申 |
| 日本 | 路径多样：研究生（预科）再考修士，或直申修士；常需研究计划书、提前联系导师；日语或英语项目 | 输出「推荐路径」而不只是录取档位；文书挖掘增加研究计划书类型；服务计划增加「联系导师」任务 |
| 韩国 | 韩语（TOPIK）或英语授课；奖学金项目对选择影响大 | 语言门槛按授课语言区分；增加奖学金匹配 |
| 德国 | 中国学生一般需先通过 APS 审核；公立大学多数免学费；重视本科课程与目标专业的学分对口；部分学校通过 uni-assist 递交 | 增加「课程匹配度」维度（需解析成绩单课程）；服务计划倒推 APS 时间线 |

**对其他模块的影响**：数据模型增加「申请路径」实体；服务包和签证模板按国家分别配置；院校库字段增加授课语言、APS 等国家特有项。

**建议的上线顺序**：先英国、中国香港、新加坡、澳洲（标准化高，规则版就能准，且常被混申），再美国研究生，再日本，最后韩国、德国和美国本科（路径复杂或软背景主导）。上表为概要，各国具体政策（如 APS、语言要求、奖学金）要以官方最新公布为准。

## 测评报告与线索转化

免费报告要「有用到愿意转发」，但把最有价值的部分留给顾问面谈：给结论和差距，不给完整方案和执行路径。

| 内容 | 免费报告（学生自助） | 顾问面谈后（付费或签约） |
| --- | --- | --- |
| 竞争力画像 | 六维雷达图 + 与同层次申请者对比 | 同 |
| 选校结果 | 每档展示 2–3 所代表校及理由 | 完整 8–12 所方案，含专业、截止日、预算 |
| 差距分析 | 最关键的 1–2 个短板 | 全部短板 + 按时间排好的提升计划 |
| 文书与申请策略 | 不含 | 定位、故事线、推荐信策略 |
| 形式 | 小程序内报告 + 可分享的长图（带工作室二维码） | PDF 方案书 |

**转化设计**

- **留资时机：** 前三步不要手机号，生成报告前用微信授权登录；报告末尾提供「免费 20 分钟顾问解读」预约入口和顾问企业微信。
- **顾问端自动推送：** 学生完成测评后，顾问收到一份「线索卡片」：背景摘要、测评结果、最可能的顾虑、建议的开场话题。
- **意向度评分（A/B/C 三档）：** 按入学时间远近、是否家长参与、是否预约解读、重复测评次数、预算与目标匹配度加权；A 类 2 小时内顾问联系（与业务流程 SLA 一致）。
- **长期培育：** 不急于申请的线索进入「成长计划」：每月推送一次个性化提醒（如「你关注的 XX 项目开放申请了」、「雅思出分后可以重新测一次」），重新测评即重新激活。
- **裂变：** 分享报告长图或邀请同学测评，可解锁每档多看 2 所学校或一次文书素材诊断（完整方案仍留给顾问面谈）。

## 测评与报告体验

测评是学生对产品的第一印象，目标是**手机上 3–5 分钟做完、10 秒内出报告、看完想找顾问聊**。

**问卷分步**（每屏不超过 4 题，顶部显示进度）

| 步 | 内容 | 设计要点 |
| --- | --- | --- |
| 0 落地页 | 「3 分钟测出你能申哪些学校」+ 隐私说明 | 不要求登录；只显示真实的测评人数 |
| 1 目标 | 国家 / 地区（可多选）、学位、专业方向、入学年份 | 全部点选，约 30 秒 |
| 2 学术 | 本科学校、专业、均分、排名（可跳过） | 输入学校名自动带出层次，学生不必知道自己学校是不是「双一流」；内置 4 分制 / 百分制换算 |
| 3 语言与标化 | 已考 / 未考 / 预估分 | 未考不影响出报告，只影响「补足后可申」列表 |
| 4 经历 | 科研 / 实习 / 竞赛的有无、数量、是否与目标专业相关 | 可改为上传简历自动填写，学生只需确认 |
| 5 偏好 | 预算区间、排名还是就业优先、城市 | 可跳过，默认不限 |
| 6 生成 | 微信授权登录 → 报告 | 这是唯一的留资门槛；不强制填手机号 |

通用规则：自动保存断点，下次打开从上次位置继续；跳过的题目在报告中提示「补充 XX 可让结果更准」；全程移动端优先。

**报告页结构**（从上到下）

1. **一句话定位：** 如「你在英国商科硕士申请者中属于中上水平，主攻档有 6 所可选」。
2. **竞争力画像：** 六维雷达图 + 与同层次申请者对比。
3. **选校结果：** 冲刺 / 主攻 / 保底各 2–3 所代表校，每所写一句为什么和差距。
4. **最关键的 1–2 个短板：** 及补上后能多申哪一档。
5. **补足后可申：** 因语言或先修课暂不满足门槛的项目。
6. **下一步：** 预约免费顾问解读（主按钮）、加顾问企微、分享。
7. **数据说明：** 院校信息来源与更新日期、「结果仅供参考，不代表录取承诺」。

**分享长图默认保护隐私**：只显示档位和学校，不显示姓名、本科学校和具体均分；学生可自己选择显示更多。

## 学生与家长端

签约后学生和家长用同一个小程序的两种身份：**学生做事，家长看进度**。目标是让家长不用反复问顾问「现在到哪了」。

| 功能 | 学生 | 家长 |
| --- | --- | --- |
| 我的进度 | 9 个服务阶段 + 当前任务 | 同，只读 |
| 待我完成 | 上传材料、确认定校、文书对话与写作、确认递交信息 | 缴费、签字类确认（如合同变更） |
| 定校清单 | 逐校「同意 / 想讨论」 | 可查看并留言，不能代替学生确认（未成年学生除外） |
| 文书 | 素材对话、在线写作、查看批注 | 默认看不到正文和对话，学生可授权 |
| 申请与结果 | 各校状态、截止日、录取结果 | 同，只读 |
| 周报 | — | 每周一份：本周完成、下周计划、需要家长做的事 |
| 问答 | 24×7 AI 问答（事实类带来源，建议类转顾问） | 同 |
| 评价 | 关键节点后的满意度评价 | 同 |

**绑定与边界**：家长通过学生发出的邀请绑定；学生未满 18 周岁时，家长为主账号，可代为确认。家长端看不到内部备注和顾问之间的沟通。

## AI 能力平台

各业务域的 AI 功能都跑在统一的 AI 平台上，不各自直连大模型：这样质量可评测、成本可控、输出可审计，也能按租户配置。

> 图：智能体分层 · 五层 + 顾问审核（图在在线文档中查看：https://claude.ai/code/artifact/3f423242-8dd1-4136-99ec-c924c5bddfc5）

| 组件 | 做什么 |
| --- | --- |
| Agent 编排 | 调度智能体按意图把任务派给场景 Agent（测评、咨询、文书、申请、内容）；场景 Agent 只能调用白名单内的工具 |
| 工具层 | 院校查询、选校引擎、档案读写、日历、消息、CRM；每个工具按调用者身份做权限校验 |
| 知识库 | 平台公共库（院校要求、签证政策）+ 租户私有库（案例、话术、内部资料）；带来源、版本和生效日期 |
| 提示词与版本管理 | 提示词模板化、版本化，支持灰度发布和回滚；租户可覆盖语气、品牌名等变量 |
| 评测中心 | 每个 Agent 配评测集（如 200 条真实咨询问题 + 标准答案）；提示词或模型变更前必须跑评测，事实错误率不升才能发布 |
| 模型路由与成本 | 按任务选模型（解析用便宜模型，文书批注用强模型）；主模型不可用时自动切换；按租户统计 token 和费用，设月度预算 |
| 安全护栏 | 输入去标识化；输出过滤（录取承诺、违规广告词、代写整篇文书）；提示词注入防护 |
| 人工审核策略 | 按输出类型配置：直接发出 / 顾问确认后发出 / 禁止 AI 生成；审核队列与修改记录回流评测集 |
| 可观测与审计 | 每次调用记录模型、提示词版本、检索到的依据、耗时、费用、审核人；可按学生回溯「这条建议从哪里来」 |

选校打分不在大模型里：它是工具层里的确定性引擎，Agent 只调用它并解释结果。

## Agent 矩阵

把各模块里的 AI 能力明确整理为 **18 个 Agent + 1 个确定性选校引擎**，由调度智能体统一分发。每个 Agent 是一个可独立开关、评测和定制的单元——对外输出时，客户按需选用，定制也以 Agent 为单位报价。

| 域 | Agent | 服务谁 | 做什么 | 人工把关 | 客户可定制 |
| --- | --- | --- | --- | --- | --- |
| 获客 | 内容创作 | 市场 | 按平台生成稿件，事实只取自院校库和案例库 | 发布前人工审核 | 品牌语气、平台模板 |
| 获客 | 测评解读 | 学生 | 把引擎结果写成报告里的解释和短板说明 | 抽检 | 报告模板、话术 |
| 获客 | 学生 AI 顾问 | 学生、家长 | 24×7 问答，建议类转顾问 | 建议类转人工 | 知识库、转人工规则 |
| 销售 | 线索评分 | 顾问 | 意向度 A/B/C 与理由 | 顾问可改 | 评分规则 |
| 销售 | 跟进助手 | 顾问 | 跟进序列、回复草稿、会话摘要 | 顾问确认发送 | 序列与话术 |
| 销售 | 首访助手 | 顾问 | 首访提纲、异议应对、会后纪要 | 顾问确认 | 提纲模板 |
| 销售 | 方案书 | 规划顾问 | 选校方案书初稿（推荐理由、整体策略） | 顾问审定 | 模板、品牌 |
| 交付 | 选校引擎（非大模型） | 规划顾问 | 打分、分档、路径、差距反算 | 顾问调档 | 权重、参考线、阈值 |
| 交付 | 背景规划 | 规划顾问 | 按差距生成提升计划与时间表 | 顾问确认 | 资源库 |
| 交付 | 文书挖掘 | 学生 | 苏格拉底式对话、素材卡 | 文案可介入 | 题库、空话词表 |
| 交付 | 文书批注 | 学生、文案 | 提问式批注、句子级建议 | 文案终审 | 批注风格 |
| 交付 | 材料核对 | 申请专员 | 缺失检查、网申信息一致性 | 专员确认递交 | 检查规则 |
| 交付 | 面试模拟 | 学生 | 语音模拟与评分 | — | 题库 |
| 交付 | 签证助手 | 签证专员、学生 | 按国家生成清单、检查文件 | 专员复核 | 国家模板 |
| 交付 | 家长周报 | 顾问、客服 | 每周进展草稿 | 确认后发送 | 模板、频率 |
| 交付 | 交接摘要 | 主管 | 换顾问时生成学生现状与风险 | 主管确认 | — |
| 运营 | 院校信息抽取 | 数据运营 | 官网变更 → 字段 → 变更单 | 人工审核发布 | 监控范围 |
| 运营 | 案例结构化 | 顾问 | 历史案例 / 录取结果结构化并脱敏 | 人工核验 | 字段 |
| 运营 | 经营分析 | 老板 | 看板问答、每周经营小结 | 只读 | 指标口径 |

与「师说 16 个 Agent」的说法相比，规模相当；区别在于这些 Agent 共用同一份学生数据、有统一的审核和审计，并且可以按客户定制。

## 核心数据模型

一个「人」从线索变成学生是同一条记录的状态变化，而不是复制一份；这是「获客到交付一体」在数据上的保证。所有实体都带租户和组织归属。

| 实体 | 关键字段 | 与谁关联 |
| --- | --- | --- |
| 客户（人） | 身份信息（加密）、生命周期状态：线索 / 学生 / 结案 | 一人一条，家长为关联联系人 |
| 背景档案 | 测评同一套维度，带版本 | 客户 1:1，历史版本 1:N |
| 测评记录 | 当时的背景快照、算法版本、结果、渠道参数 | 客户 1:N |
| 商机 | 阶段、负责人、意向度、流失原因 | 客户 1:N（允许二次咨询） |
| 合同 | 服务包、金额、分期、状态 | 商机 1:1，收款 1:N |
| 服务计划 | 里程碑、当前阶段、服务小组 | 合同 1:1，任务 1:N |
| 任务 | 类型、负责人、SLA、状态 | 服务计划 / 申请 / 文书 |
| 定校清单 | 版本、学生确认状态 | 学生 1:N（版本），项目 N:M |
| 申请 | 项目、轮次、材料状态、结果 | 定校清单项 1:1 |
| 文书 | 题目、版本、状态、批注 | 申请 N:1，素材卡 N:M |
| 素材卡 | 见「模块详细设计」 | 学生 1:N |
| 项目（院校库） | 要求、截止日、字段溯源 | 平台公共数据，全租户共享 |
| 录取案例 | 背景特征、结果、核验等级、授权 | 申请结果自动生成，与身份分开存 |
| AI 调用记录 | 模型、提示词版本、依据、审核人、采纳结果 | 挂在对应业务对象上 |

## 异常与边界场景

留学服务周期长，下面这些情况每个申请季都会发生，系统要有明确的处理方式。

| 场景 | 系统怎么处理 |
| --- | --- |
| 中途换顾问 | 主管发起转交，未完成任务一并转移；新顾问自动收到「交接摘要」（AI 生成，含当前风险）；通知学生和家长 |
| 退费 / 解约 | 按合同退费规则计算可退金额（已完成里程碑扣除），财务审批；服务计划冻结，数据按协议保留或删除 |
| 延期一年申请 | 服务计划整体顺延，定校清单标为「待更新」，新申请季开放时自动重算档位 |
| 换国家 / 加申国家 | 背景档案不变，按新组合重算；可能涉及合同变更（增项），走补充协议 |
| 全部被拒 / 二次申请 | 自动生成「申请复盘」初稿（档位是否准、材料问题）；结果仍进案例库；商机以「二次申请」重新开启 |
| 学生与家长意见不一致 | 定校确认以学生为准（未成年除外），家长的留言提醒顾问安排三方沟通 |
| 学生长时间失联 | 连续 N 天未响应任务自动升级：顾问 → 家长 → 主管；临近截止的申请标红 |
| 项目要求临时变更 | 见「信息更新」：受影响学生和顾问收到提醒，已递交的申请不受影响 |
| 学生要求 AI 代写文书 | 拒绝并解释，通知文案老师；记录但不惩罚 |
| 家长投诉 | 自动创建投诉工单，主管 24 小时内响应；进入质量管理统计 |
| 用户要求删除个人信息 | 身份信息删除或匿名化；已脱敏的案例按授权条款处理；保留法定必须的财务记录 |

## 上线与使用便捷

企业级的角色、权限和流程对 10 人以内的创业工作室太重，所以产品提供一个**工作室模式**：同一套系统，默认配置大幅简化，人多了再逐项打开。

| 方面 | 工作室模式 | 公司模式 |
| --- | --- | --- |
| 角色 | 3 个：顾问（含咨询、规划、申请）、文案、负责人 | 12 类岗位角色 |
| 导航 | 6 项：今日工作台、线索、学生、选校、文书、院校库 | 13 项，按角色显示 |
| 审批 | 关闭（报价、导出不审批，仍留痕） | 按规则审批 |
| 分配 | 手动或全部归创始人 | 规则自动分配 |
| 服务包与流程 | 内置 3 个模板（全程 / 半 DIY / 单项文书） | 可自定义 |

**初始化向导（第一次登录约 30 分钟）**

1. 填工作室名称、品牌色、二维码 → 报告和方案书自动套用。
2. 选主做的国家和学位 → 自动启用平台已有的项目数据和默认权重。
3. 邀请同事、选角色。
4. 导入已有客户（Excel 模板，字段自动匹配，导入前预览和查重）。
5. 导入历史录取案例（Excel 或粘贴文本，AI 结构化后逐条确认）。
6. 生成自己的测评链接和二维码。

**降低数据录入负担**：项目数据由平台统一维护，租户只补充自己关心但库里没有的项目（粘贴官网链接，AI 预填字段，人工确认）。工作室阶段，平台方就是自己，这部分工作量要计入成本。

**培训与帮助**：每个页面右上角有一分钟操作说明；首周每天首页推送一个「今天试试这个功能」；AI 助手可回答「这个功能怎么用」。

## 技术架构

从「模块化单体 + 多租户」起步：代码按业务域划好边界，部署上先合并，哪个域压力大就先拆成独立服务。这样工作室阶段小团队维护得了，客户多了也不用重写。

| 层 | 设计 |
| --- | --- |
| 多租户 | 默认共享数据库、每表带 tenant_id，用 PostgreSQL 行级安全强制隔离；大客户可独立数据库或私有化部署；租户配置（品牌、域名、功能开关、套餐）集中管理 |
| 前端 | 管理后台 Web（各岗位工作台）、学生 / 家长小程序、测评 H5、企业微信侧边栏（顾问聊天时直接看学生档案和 AI 建议） |
| 业务域服务 | 组织与权限、营销与内容、CRM、交付、测评与选校引擎、AI 平台、院校数据、财务、消息、文件；域之间只通过接口和事件交互，不跨域直连数据表 |
| 事件与数据流 | 关键业务事件（线索创建、签约、阶段变更、录取结果）写入事件表 / 消息队列，驱动通知、SLA 计时、算法回流和数仓同步 |
| 存储 | PostgreSQL（业务库 + pgvector 知识检索）、Redis（缓存、限流）、对象存储（材料文件，加密）、分析库（经营报表，数据量大后引入） |
| 开放能力 | OpenAPI + Webhook（对接客户已有的 CRM、财务系统）、可嵌入测评组件、企业微信 / 飞书 / 钉钉单点登录 |
| 可观测与可用性 | 统一日志、链路追踪、告警；对外版可用性目标 99.9%；库每日备份、定期恢复演练 |
| 工程化 | 容器化部署、开发 / 测试 / 生产三套环境、CI 自动化测试、数据库迁移脚本版本化 |

后端可沿用 Spring Boot + PostgreSQL（与已有 RuoYi-Vue 工程同栈，组织权限、定时任务可复用），但需补上多租户改造；大模型调用统一走 AI 平台，不在业务代码里直连。

**开发方式：以 AI 开发为主**

代码主要由 AI 编程助手生成，人负责需求、评审、测试和上线。这能大幅减少编码人力，但瓶颈会转到需求清晰度和质量把关上。

1. **本文档即需求输入：** 按模块拆成「用户故事 + 验收标准 + 数据表」的小任务再交给 AI，一个任务一个分支、一次合并。
2. **先测试后功能：** 选校引擎、权限、租户隔离、计费等关键逻辑先写测试用例，由 AI 实现到测试通过。
3. **人工评审不可省：** 至少一名能读懂代码的工程师评审每次合并；安全相关代码（登录、权限、加密、支付）逐行审，并做安全扫描。
4. **沿用成熟框架：** 优先复用已有脚手架和开源组件，减少 AI 自由发挥的范围，便于后期维护。
5. **AI 不能代替的工作要单独排期：** 微信小程序与企业微信的资质、审核和接入；院校数据的人工核对；顾问试用与反馈。

**定制化架构**

定制与升级的矛盾靠「核心不动、外层可变」解决：

- **配置中心：** 品牌、服务包、权限、算法参数、Agent 开关与提示词变量都存在配置表里，可导出 / 导入，升级时自动保留。
- **元数据驱动的自定义字段与表单：** 客户新增字段不改数据库结构，可用于列表、筛选、报表和 Agent 的上下文。
- **流程引擎：** 服务阶段、任务模板、审批和 SLA 用可视化配置，不写死在代码里。
- **扩展点：** 业务事件（线索创建、签约、阶段变更、录取结果）对外发出，定制代码订阅事件或调用开放接口实现；界面留有可插入的入口与标签页。
- **Agent 插件：** 新 Agent 按统一接口接入 AI 平台，自动获得权限、审核、审计和评测。
- **版本策略：** 核心产品按季度发版；每个客户的定制有独立的回归测试，升级前自动跑一遍。

## 安全与合规

平台处理大量未成年人和家庭的敏感信息，对外销售时客户一定会问安全资质；这些要求在工作室阶段就按标准建，后补成本更高。

| 领域 | 要求 | 何时完成 |
| --- | --- | --- |
| 个人信息保护 | 隐私政策与单独同意（敏感信息、向第三方提供）；不满 14 周岁监护人同意；最小化收集；用户可查询、更正、删除、注销 | 上线前 |
| 租户隔离 | 所有查询强制带租户条件（数据库行级安全）；租户数据不用于其他租户或模型训练 | 上线前 |
| 数据安全 | 传输 TLS、敏感字段加密、网申账号密码独立加密保管；定期备份与恢复演练 | 上线前 |
| 审计日志 | 登录、查看敏感字段、导出、权限变更、AI 输出审核全部留痕，保存不少于 6 个月 | 上线前 |
| 生成式 AI | 使用已备案的大模型服务；AI 生成内容按规定标识；对外提供智能问答服务前评估是否需要算法备案 | 对外开放前 |
| 网络安全等级保护 | 按等保二级要求建设，对外销售前完成定级备案与测评（大客户可能要求更高） | 产品化前 |
| 广告与宣传 | 不承诺录取、不用「保录」「录取率 XX%」等无法证实的表述；案例脱敏并取得授权 | 上线前 |
| 学术诚信 | 文书功能不生成可直接提交的整篇正文，保留学生写作版本记录 | 上线前 |
| 服务合同 | 服务内容、退费规则、不承诺录取条款；对外销售时加数据处理协议（平台作为受托处理方） | 分别在上线前 / 产品化前 |
| 平台与资质 | 确认营业执照经营范围覆盖留学咨询；确认小程序所选服务类目需要的资质；企业微信会话存档按官方要求取得客户同意；各内容平台的营销与导流规则 | 上线前 |

法规要求为概要，具体义务和时点请律师与安全服务商确认。

## 分阶段路线

蓝图按公司级一次设计完，建设分三期：每期都在同一套多租户底座上加模块，工作室作为第一个租户先用、先验证；是否对外销售由阶段二结束时的真实数据决定。

**阶段一再拆两步**：

- **1a 获客最小闭环（约 8–10 周）：** 测评问卷 + 打分引擎 + 报告页、线索看板、企业微信加好友与侧边栏（客户信息）、院校库录入后台。数据表从第一天带 tenant_id，但不做租户管理界面。
- **1b 工作台与内容（再 8–10 周）：** 今日工作台、学生档案、选校工作台与方案书、内容生产助手、组织权限。

1a 上线即可开始冷启动，1b 在种子期内逐步上线。周数为粗估。

**是否产品化的判断标准**（阶段二结束时逐条看）：

- [ ] 测评渠道的每单获客成本明显低于其他渠道
- [ ] 打分引擎经过一季录取结果校准，各档实际录取率与档位一致
- [ ] 顾问不需要开发帮忙就能自己维护项目和权重
- [ ] 有同行或语培机构主动询问或愿意试用
- [ ] 多租户隔离、审计和备份恢复通过第三方安全评估

五条都满足再考虑对外卖。对外时优先卖「测评组件」给语培和国际学校（不与自己抢学生），卖工作台给同行会把自己的方法交给竞争对手，要更谨慎。

阶段一上线后的冷启动和种子用户获取见 冷启动与种子用户。

## 输出与定制化方案

对外输出的核心是 **80% 标准产品 + 20% 定制**：标准部分保证交付快、可升级，定制部分满足每家公司的品牌、流程和业务重点。比例为设计目标。

**交付形态**

| 形态 | 适合 | 说明 |
| --- | --- | --- |
| SaaS 标准版 | 10 人以内、不想维护服务器的工作室（与我们同类，主推） | 多客户共用，只做配置级定制，上线最快 |
| 独立部署版 | 定制需求多、或要求数据自己保管的留学公司 | 客户独立的云服务器和数据库，可做全部四层定制，由我方托管运维或客户自维 |
| 组件版 | 语培机构、国际学校 | 只输出测评 + 报告 + 线索导出，嵌入对方公众号或官网 |

**四层定制**（从便宜到昂贵，尽量用上层解决）

| 层级 | 可定制内容 | 谁来做 | 是否影响升级 |
| --- | --- | --- | --- |
| 1 品牌与配置 | Logo、配色、域名、报告与方案书模板、服务包、SLA、角色权限、算法权重与参考线 | 客户自己或实施顾问，无代码 | 否 |
| 2 低代码 | 自定义字段与表单、流程节点与审批、报表、跟进序列、通知模板 | 实施顾问 | 否 |
| 3 Agent 定制 | Agent 的知识库、提示词变量、审核策略、开关；客户自有案例导入训练参考线 | 实施顾问 + AI 工程师 | 否（升级前跑评测） |
| 4 扩展开发 | 对接客户已有的 CRM / 财务 / OA、新增业务模块、新增 Agent | 开发团队（以 AI 编程为主） | 只通过扩展点开发，不改核心 |

**实施流程**（独立部署版，典型约 4–8 周，视定制量而定）

1. **需求调研（1 周）：** 对照本文档的标准流程，只记录「差异点」，形成定制清单并分到四层。
2. **部署与配置（1–2 周）：** 独立环境部署、品牌与配置、角色权限。
3. **数据迁移（1 周）：** 导入客户、学生、历史案例，校准客户自己的参考线。
4. **定制开发（按需）：** 第 2–4 层定制，每项有验收标准。
5. **培训与试运行（1–2 周）：** 按岗位培训，试运行期间每周复盘。
6. **上线与运维：** 版本升级、院校数据更新、故障响应按年度服务协议。

**收费构成（草案）**

| 项目 | 计费方式 |
| --- | --- |
| 产品授权 / 订阅 | SaaS 按席位年费；独立部署按版本授权或年费 |
| 实施服务 | 按周或打包（部署、配置、迁移、培训） |
| 定制开发 | 按定制清单逐项报价；Agent 定制按个数报价 |
| 年度服务 | 升级、院校数据更新、运维支持，按年收费 |
| AI 用量 | 套餐内含额度，超出按量计费；也可由客户自己提供大模型账号 |

具体价格待种子客户验证。**院校数据库是持续收入和客户粘性的关键**：即使独立部署，院校数据也由我方统一维护并同步。输出给同行意味着把自己的方法交给竞争对手，建议优先选择不同城市或不同主做国家的公司。

## 指标、成本与风险

只盯一条主线：**每签一个客户花了多少钱和时间**；其余指标都是它的拆解。

**关键指标**

| 环节 | 指标 | 定义 |
| --- | --- | --- |
| 引流 | 测评开始数（按渠道） | 每条内容 / 每个渠道带来的测评数 |
| 测评 | 完成率 | 开始 → 拿到报告 |
| 留资 | 预约解读率 | 拿到报告 → 加企微或预约 |
| 转化 | 首访到签约率 | 对比其他渠道来的客户 |
| 传播 | 分享率 | 拿到报告后分享或邀请的比例 |
| 提效 | 单份选校方案耗时、顾问人均在服学生数 | 上线前后对比 |
| 算法 | 顾问改档率、各档实际录取率 | 顾问调整档位的比例；录取季后的校准 |

上线前用「冷启动与种子用户」页的规划假设排计划；上线后跑满一个月拿到真实基线，再替换为正式目标。

产品化后增加平台级指标：付费租户数、租户续费率、年经常性收入（ARR）、单租户 AI 成本、各模块活跃率。

**成本构成**（金额待估算）

- 开发：系统主要由 AI 编写，按「分阶段路线」的 1a → 1b 顺序推进；成本主要是 AI 编程工具与大模型的订阅费，以及需求确认、测试和验收所需的时间。
- 运行：云服务器、小程序认证、大模型 API（测评打分不走大模型，调用量主要来自材料解析、报告解释、内容生成）。
- 数据：顾问录入和维护常申项目的时间，是最容易被低估的一项。

**主要风险**

| 风险 | 应对 |
| --- | --- |
| 测评结果不准，反而伤工作室口碑 | 只展示档位不展示概率；先覆盖主做的 2–3 个国家；顾问定期抽检报告 |
| 有测评没流量 | 内容生产助手与测评同期上线；每条内容挂测评入口，按渠道统计效果 |
| 免费报告给太多，学生拿完就走 | 报告只给结论和差距，完整方案和执行路径留给面谈 |
| 顾问不用工作台 | 从顾问最烦的事（做方案、写内容）开始；工作室规定线索只在工作台里跟进 |
| 录取结果回流慢，算法长期停在规则版 | 签约合同里约定录取结果归档；允许测评用户自愿回填结果换取福利 |
